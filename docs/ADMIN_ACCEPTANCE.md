# Приёмка админки (этап 9)

## Что покрыто автоматически

| Проверка | Где |
| --- | --- |
| Публичные страницы открываются, один H1, нет ошибок консоли и 5xx | `tests/e2e/public-smoke.spec.ts` |
| Все разделы админки открываются под админом без ошибок консоли/сети | `tests/e2e/admin-smoke.spec.ts` |
| Состояние списков (поиск, фильтры) живёт в URL и переживает F5 и «назад» | `tests/e2e/admin-lists.spec.ts` |
| CRUD: создание → правка → перезагрузка → удаление с подтверждением | `tests/e2e/admin-crud.spec.ts` (`E2E_WRITE=1`) |
| Матрица прав и доступ ролей к маршрутам | `src/lib/permissions.test.ts` |
| Уникальность и инвалидация ключей кэша | `src/lib/query-keys.test.ts` |
| Валидация форм и разбор ошибок Postgres/Zod | `src/lib/admin/schemas.test.ts`, `src/lib/admin/form-errors.test.ts` |
| Автосейв черновиков и статусы сохранения | `src/routes/__tests__/admin-editors.smoke.test.ts`, `src/components/admin/SaveStatus.test.tsx` |

## Как запускать

```bash
bun run test                      # юнит-тесты
bun run test:e2e                  # публичные страницы (без логина)

E2E_ADMIN_EMAIL=... E2E_ADMIN_PASSWORD=... bun run test:e2e          # + админка
E2E_ADMIN_EMAIL=... E2E_ADMIN_PASSWORD=... E2E_WRITE=1 bun run test:e2e  # + CRUD

PW_BASE_URL=https://event-hub.by bun run test:e2e                    # против прод-домена
```

Без переменных `E2E_ADMIN_*` админские сценарии помечаются `skipped` — CI не падает
на форках и внешних PR.

## Ручной чек-лист перед релизом

1. Вход четырьмя ролями (админ, менеджер, бухгалтер, контент-редактор): в меню видны только доступные разделы, прямой переход в чужой раздел даёт понятный отказ.
2. Заказ: создание из корзины → смена статуса → отметка оплаты → генерация КП/счёта в PDF.
3. Документы: КП → отправка ссылки клиенту → просмотр по токену → принятие.
4. Каталог: правка позиции, автогенерация slug, публикация, проверка страницы на сайте.
5. Уход со страницы с несохранёнными правками показывает предупреждение.
