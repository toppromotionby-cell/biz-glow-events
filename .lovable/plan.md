# Новый универсальный бот-помощник в Telegram

Отдельный третий бот (рядом с планером и DJ-ботом): полноценный помощник по админке сайта — знает все документы и файлы, присылает их в Telegram в PDF, ищет в интернете, ведёт и пополняет базу знаний и следит за гигиеной данных. Строго по прописанной роли, без самодеятельности.

## Что нужно от вас

1. Создать бота в @BotFather (`/newbot`) и прислать **@username** и **токен**.
2. В @BotFather: `/setprivacy` → Disable (если планируете добавлять его в группы). Описание и меню команд настрою сам.
3. Напишите новому боту `/start` — он выдаст код привязки, вводите его в админке.
4. По желанию: ID рабочего чата, если бот должен отвечать и в группе.

Токен подключу как отдельное подключение Telegram-коннектора — вручную нигде хранить не нужно.

## 1. Работа с админкой и файлами

Бот видит те же данные, что и вы в админке, и ровно в тех правах, что у привязанного аккаунта (RLS + проверка роли на каждый запрос).

- **«Какие есть файлы»** — по запросу выдаёт список: КП, документы, презентации, кадровые документы, счета/акты, медиа каталога, треки DJ-хаба. С фильтрами: за период, по клиенту, по типу, по статусу, по автору.
- **Поиск** — «найди КП для Белтелеком за август», «покажи последние 5 договоров займа» → карточки с кнопками `📄 PDF` · `🔎 Открыть в админке` · `ℹ️ Детали`.
- **Отдача файлов** — по кнопке или фразе «пришли PDF» бот генерирует документ на сервере (тем же генератором, что и админка — превью и PDF совпадают) и отправляет файлом в чат. Для больших файлов — ссылка с истечением срока.
- **Внутренние версии** — документы с себестоимостью/маржой отдаются только пользователям с правами админа и всегда с пометкой «внутреннее, не для клиента».
- **Сводки** — «что нового за неделю», «сколько КП в работе», «какие документы без реквизитов» → таблица/график картинкой.
- **Действия с данными** (создать черновик, изменить статус, отправить письмо) — только через подтверждение кнопкой; массовые и необратимые — через план на утверждение.

## 2. База знаний: единый мозг проекта

Сегодня знания разбросаны (информационная база, справочник документов, память ассистента). Сводим в один слой знаний с источниками.

**Что туда попадает автоматически:**
- всё, что заносится через админку: новые клиенты, позиции, шаблоны, реквизиты, цены, статьи информационной базы, настройки документов — по событию сохранения;
- итоги диалогов с ботом: подтверждённые факты, решения, договорённости, новые правила («логотип для BeLight брать вот такой»);
- результаты интернет-поиска, которые вы пометили как полезные (кнопка `💾 В базу знаний` под ответом);
- документы и КП: ключевые параметры (клиент, услуги, цены, условия) — как факты, а не файл целиком.

**Как это работает:** каждая запись знания = факт + источник + дата + автор + срок актуальности + уверенность. Записи из админки создаются автоматически по алгоритму (правила извлечения по типу сущности), записи из диалога — с вашим подтверждением, если бот не уверен. Дубликаты и противоречия склеиваются: бот показывает «было / стало» и просит выбрать, если сам решить не может.

**Как используется:** любой ответ бота сначала смотрит в базу знаний, потом в базу данных, и только потом в интернет. В ответе всегда видно, откуда взято.

## 3. Интернет-поиск

Каскад бесплатных источников: DuckDuckGo → Wikipedia → чтение 2–3 найденных страниц. Осмысление — моделью Gemini 3.7 Flash через Lovable AI. Всегда указываются ссылки. Если ничего не найдено или источники противоречат — бот говорит это прямо, а не выдумывает.

## 4. Гигиена данных и авто-аудит

Единый планировщик проверок (расширяем то, что уже есть в DJ-хабе, на весь проект). Раз в сутки/неделю проверяется:

```text
Документы     → черновики старше 60 дней, КП без ответа, документы без реквизитов
Клиенты       → дубликаты, пустые контакты, неактуальные реквизиты
Каталог       → позиции без цены/фото, снятые с публикации, устаревшие цены
Медиа         → файлы без ссылок (сироты), тяжёлые изображения, битые ссылки
DJ-хаб        → спящие треки, дубликаты, отсутствующие метаданные
База знаний   → просроченные факты, противоречия, знания без источника
Почта/рассылки→ отказавшие адреса, зависшие очереди
Календарь     → сбои синхронизации, просроченные задачи
```

**Автоматика vs ручная модерация.** Каждое правило имеет уровень уверенности:
- уверенно и безопасно (пересчёт, нормализация, архивирование очевидного мусора) — делается само, в чат уходит короткий отчёт «сделано: 12 действий»;
- неоднозначно (какой из двух клиентов оставить, удалять ли трек с 3 скачиваниями) — карточка в Telegram с кнопками `✅ Так` · `↔️ Иначе` · `⏭ Пропустить` · `🚫 Больше не спрашивать`;
- опасно (удаление, массовые изменения) — только вручную, с планом и подтверждением.

Ваши решения по спорным случаям запоминаются как правила — со временем ручных вопросов становится меньше.

## 5. Режимы и строгость роли

```text
Простой вопрос / поиск / выдача файла → сразу, со ссылками и источниками
Нестандартная задача                  → план на утверждение (✅ · ✏️ · 🚫)
Изменение данных                      → подтверждение кнопкой
Опасное/массовое действие             → только план + подтверждение
Вне зоны ответственности / нет прав   → вежливый отказ + что умеет
Не привязанный пользователь           → только /start
```

**Роль прописывается полностью** отдельным файлом: кто он, кому подчиняется, чем занимается и чем НЕ занимается; формат ответа (сначала суть, максимум 5 пунктов, без «воды»); обязательные источники; запрет выдумывать факты, цифры и цитаты; запрет выдавать ключи, пароли и внутренние данные не тем ролям; что делать при неоднозначности (один уточняющий вопрос, не гадать); что делать при ошибке инструмента, пустом результате, таймауте, повторе; сценарии на все типовые случаи.

## 6. Команды

`/start`, `/help`, `/files [фильтр]`, `/doc <поиск>`, `/pdf <документ>`, `/ask <вопрос>`, `/find <запрос>` (только интернет), `/kb <поиск>` и `/kb add <факт>`, `/hygiene` (отчёт и запуск проверки), `/plan <задача>`, `/stats [период]`, `/sources`, `/mode`, `/reset`, `/mute`, `/unmute`.

## 7. Админка

Раздел `/admin/assistant`:
- статус вебхука, перерегистрация, проверка связи;
- привязанные пользователи и их роли, лимиты;
- журнал диалогов, планов, выданных файлов (кто что получил);
- база знаний: просмотр, правка, источники, срок актуальности, ручное добавление;
- правила гигиены: включение, расписание, пороги, «что делать само / что спрашивать»;
- очередь ручной модерации с теми же решениями, что и в Telegram.

## Техническая часть

- **Миграция:** `assistant_bot_links`, `assistant_bot_codes`, `assistant_bot_updates` (дедуп по `update_id`), `assistant_bot_messages` (журнал), `assistant_bot_settings`, `assistant_file_grants` (аудит выдачи файлов), `knowledge_facts` (факт, источник, сущность, срок, уверенность, автор), `knowledge_sources`, `hygiene_rules`, `hygiene_findings` (статус: авто-исправлено / на модерации / отклонено). Для каждой таблицы GRANT + RLS: свои строки пользователю, полный доступ админам, `service_role` серверу.
- **Вебхук:** `src/routes/api/public/assistant/webhook.ts` — timing-safe проверка `X-Telegram-Bot-Api-Secret-Token`, дедуп `update_id`, мгновенный `200`, обработка в фоне.
- **Транспорт:** `src/lib/assistant/transport.server.ts` — отправка сообщений, документов и картинок через connector-gateway, ретраи, разбивка длинных сообщений.
- **Файлы:** `src/lib/assistant/files.server.ts` — единый реестр источников (КП, документы, презентации, paperwork, медиа, DJ) + вызов существующих PDF-генераторов, без дублирования логики.
- **Знания:** `src/lib/knowledge/` — извлечение фактов из событий админки (триггеры/хуки на сохранение), дедупликация, разрешение противоречий, поиск по фактам.
- **Гигиена:** `src/lib/hygiene/` — реестр правил, планировщик через pg_cron → `/api/public/hooks/hygiene`, исполнение, отчёты, эскалация в Telegram.
- **Мозг:** `src/lib/assistant/agent.server.ts` — Gemini 3.7 Flash через Lovable AI Gateway, инструменты `search_files`, `send_document`, `query_db`, `kb_search`, `kb_add`, `web_search`, `read_page`, `hygiene_report`, `make_plan`. Мутирующие инструменты — с обязательным подтверждением. Без искусственных таймаутов; 402/403/429 обрабатываются по контракту гейтвея с понятным сообщением в чат.
- **Персона:** `src/lib/assistant/persona.ts` — полный текст роли и правил.

## Проверки, чтобы не ломалось

- Тесты прав: пользователь без роли админа не получает внутренние документы и чужие данные (проверяется отдельным набором кейсов).
- Тесты инструментов: поиск файлов, генерация PDF, извлечение фактов, дедуп знаний, срабатывание правил гигиены на подготовленных данных.
- Тест персоны: ~20 типовых запросов — бот не выходит за роль, всегда даёт источники, не выполняет мутации без подтверждения.
- Дедуп `update_id` и повторная доставка Telegram.
- Health-check `/api/public/assistant/health`: вебхук, последний апдейт, доступность модели, состояние очередей гигиены; при сбое — уведомление вам в Telegram.

## Порядок работ

1. Миграция (бот, знания, гигиена) + RLS + GRANT.
2. Транспорт, вебхук, привязка по коду, права.
3. Персона и агент с инструментами.
4. Работа с файлами и отдача PDF в Telegram.
5. База знаний: авто-наполнение из админки + пополнение из диалога.
6. Интернет-поиск с цитированием.
7. Гигиена: правила, расписание, авто-исправления, очередь ручной модерации.
8. Админка `/admin/assistant` и health-check.
9. Тесты и проверка в реальном чате после получения токена.
