# Document Builder: Company → Brand Kit → Template → Document

Перевожу раздел «Документы и шаблоны» с модели «редактор текста» на явную четырёхуровневую архитектуру, чтобы завтра счёт, акт или договор добавлялись как новый *тип документа*, а не как новая подсистема.

## Что меняется по сущностям

```text
Company (company_profiles, уже есть)
  └── Brand Kit (несколько на компанию, один по умолчанию)
        └── Template (структура + переменные + тип документа)
              └── Document (значения переменных + снимок блоков + статус)
```

### 1. Company
Остаётся существующий профиль компании — источник реквизитов, подписанта, логотипа, банка. Ничего не дублируем.

### 2. Brand Kit (вместо «фирменного бланка»)
Сейчас настройки бланка — одна запись на компанию. Делаю их полноценной сущностью: у компании может быть несколько наборов (например «Официальный бланк», «Маркетинговый», «Без шапки для печати на готовом бланке»), один помечен как основной. Документ ссылается на конкретный набор; при смене компании подставляется её основной набор.

Отдельная страница «Фирменные стили»: список наборов по компаниям, дублирование, переименование, назначение основного, живое A4-превью.

### 3. Template
Шаблон получает явный контракт: тип документа, категория, список блоков, **декларацию переменных** (ключ, подпись, тип поля: строка / многострочный текст / дата / число / деньги, обязательность, значение по умолчанию, источник — авто из компании или ручной ввод). Сейчас переменные вычисляются только сканированием текста; переходим на объявленную схему + автодополнение найденными в тексте.

Шаблон может ограничиваться конкретной компанией или быть общим. Версионирование: у шаблона есть номер ревизии, документ хранит, из какой ревизии создан.

### 4. Document
Документ хранит снимок блоков (правки не ломают шаблон), значения переменных, тип, номер, дату, статус, компанию и бренд-набор. Нумерация — по правилу типа документа (счётчик в год, префикс из типа), как уже сделано для КП и финдокументов.

## Реестр типов документов — главный элемент масштабирования

Ввожу единый реестр `document-kinds`: одно описание на тип (письмо, приказ, доверенность, справка, уведомление, служебная записка, **счёт**, **акт**, **договор**, произвольный). Каждый тип объявляет:
- название, категорию, иконку;
- набор обязательных переменных;
- правило нумерации;
- разрешённые блоки (например, у счёта обязательны блок «позиции с суммами» и блок «банковские реквизиты»);
- пресеты шаблонов.

Добавление счёта/акта/договора после этого = запись в реестре + пресет шаблона. Ни редактор, ни PDF, ни DOCX, ни импорт не трогаются.

Дополнительно добавляю два блока, которых требуют финансовые формы, чтобы реестр был не декларацией, а рабочим механизмом:
- **Позиции с суммами** — таблица со столбцами (наименование, кол-во, цена, сумма), автоитог и сумма прописью.
- **Реквизиты сторон** — двухколоночный блок «Исполнитель / Заказчик» с автоподстановкой из компании.

## Рендеринг

Один источник структуры для превью, PDF и DOCX сохраняется (как сейчас). Добавляю проверку паритета: превью и PDF собираются из одного нормализованного описания документа, регрессионный тест сверяет состав блоков и разбиение по страницам для каждого типа.

## Порядок работ

1. Реестр типов документов + декларация переменных в шаблоне (модель, миграция полей).
2. Brand Kit как отдельная сущность: миграция существующих настроек бланка, страница управления, выбор набора в редакторе.
3. Панель «Поля документа» на основе объявленной схемы (типы полей, валидация обязательных).
4. Новые блоки: позиции с суммами, реквизиты сторон; поддержка в HTML/PDF/DOCX.
5. Пресеты счёта, акта, договора поверх реестра — как доказательство расширяемости.
6. Версии шаблонов и «обновить документ до новой ревизии шаблона».
7. Тесты: подстановка переменных, нумерация по типам, паритет превью/PDF.

## Техническая часть

- Миграции: `paperwork_brand_kits` (company_profile_id, name, is_default, settings jsonb) с переносом данных из `paperwork_brand_blanks`; `paperwork_templates` += `variables_schema jsonb`, `revision int`; `paperwork_documents` += `brand_kit_id`, `template_revision`.
- GRANT + RLS по текущей схеме раздела (автор видит свои документы, admin/manager — все).
- Код: `src/lib/paperwork/kinds.ts` (реестр), `variables.ts` → работа со схемой, `model.ts` += блоки `items`/`parties`, поддержка в `html.ts`, `pdf.server.ts`, `docx-export.server.ts`; серверные функции бренд-наборов в `paperwork.functions.ts`; маршрут `admin.paperwork.blanks.tsx` → управление бренд-наборами.
- Существующие документы и шаблоны переносятся автоматически: у каждого документа проставляется основной бренд-набор компании, схема переменных генерируется из текста шаблона.

## Отмечу
Счета и акты по заказам, которые уже формируются в разделе заказов (`/admin/orders/$id/invoice`, `/act`), остаются на своём месте — здесь появляются их «свободные» аналоги для документооборота. Если нужно свести обе ветки в одну, это отдельный шаг после пункта 5.
