# Единое исправление генерации и скачивания документов

## Цель
Устранить 500/502 не только в основном КП, а во всех сценариях генерации, просмотра, скачивания и отправки документов. Пользователь не должен видеть технические ответы вроде `Internal server error`.

## Что подтверждено проверкой
- В production-логах 502 возникает на PDF-маршруте КП: серверный runtime завершает зависший запрос до формирования ответа.
- PDF для КП, промо-КП, счёта, договора, акта и вложений писем собираются одним генератором `src/lib/documents/pdf.server.ts`; шрифты в текущем коде уже встроены в сборку и не загружаются через сеть.
- Защищённый `try/catch` сейчас есть только у маршрутов основного и промо-КП. Общий обработчик документов заказа и публичный PDF по ссылке могут по-прежнему вернуть необработанный 500.
- Общий просмотрщик добавляет тело ошибочного ответа в уведомление, поэтому клиент видит сырой текст `Internal server error`.
- В карточке заказа часть действий открывает HTML, хотя интерфейс обозначает их как скачивание документа; в блоке вложений дополнительно предлагается ручная печать вместо готового PDF.
- Автоматический production smoke-test проверяет только публичные страницы и health endpoint; генераторы документов тестами не покрыты.

## Изменения

### 1. Единый безопасный PDF-конвейер
- Вынести формирование PDF-ответа, безопасного имени файла и обработку исключений в общий серверный helper.
- Подключить его к:
  - основному КП;
  - промо-КП;
  - публичной ссылке КП;
  - КП, счёту, договору и акту заказа.
- Возвращать единый структурированный ответ об ошибке с идентификатором операции, не раскрывая stack trace или внутренние детали клиенту.
- Логировать на сервере тип документа, безопасный идентификатор сущности, этап (`load`, `build`, `response`) и исходную ошибку, чтобы 500/502 можно было диагностировать по журналу.

### 2. Исправление всех клиентских действий с документами
- Перевести кнопки скачивания в заказах и настройках документов на URL с `?format=pdf`, чтобы они получали настоящий PDF, а не HTML с инструкцией печати.
- Убрать дублирующие `catch/toast`: обработка ошибки останется централизованной в просмотрщике.
- Сохранить HTML-превью только там, где оно явно подписано как HTML/предпросмотр.
- Проверить XLSX-экспорт промо-КП и оставить его отдельным браузерным экспортом с понятной ошибкой.

### 3. Понятные ошибки вместо технических сообщений
- Нормализовать ошибки в `DocumentViewerProvider`: для 401/403, 404, 409, 5xx и сетевого сбоя показывать короткие русские сообщения и действие для повтора.
- Не выводить HTML, `Internal server error`, stack trace и другие сырые тела ответов в toast.
- Сохранять диагностический идентификатор ответа, чтобы администратор мог передать его для поиска в логах.
- Гарантированно сбрасывать состояние загрузки и предыдущий blob URL после ошибки или закрытия окна.

### 4. Защита фоновых сценариев
- Применить тот же безопасный вызов генератора к PDF-вложениям писем, предпросмотру писем и пакетной генерации документов заказа.
- Не отправлять письмо «как будто всё успешно», если пользователь явно запросил PDF-вложение, но оно не собрано; вернуть понятный статус и сохранить серверную причину в логах.
- Сохранить независимую обработку каждого документа при пакетной генерации, чтобы сбой одного файла не ломал остальные.

### 5. Автоматическая проверка регрессий
- Добавить unit/smoke-тест генератора на все варианты: заказное КП, счёт, договор, акт, основное КП и промо-КП.
- Для каждого результата проверять сигнатуру `%PDF-`, ненулевой разумный размер и работу с кириллицей/пустыми необязательными полями.
- Добавить тест общего PDF-response helper: корректные заголовки, ASCII fallback + UTF-8 имя и безопасный 500-ответ при исключении.
- Добавить тест нормализации клиентских ошибок, чтобы сырой `Internal server error` больше не попадал в интерфейс.
- Расширить smoke-проверку отдельным авторизованным документным сценарием для preview/production; публичный smoke-test оставить без закрытых URL.

## Проверка результата
- Запустить целевые тесты генератора и обработчиков.
- Через браузер проверить в админке PDF для КП, промо-КП, счёта, договора и акта, а также скачивание из просмотрщика.
- Проверить публичную ссылку КП и её PDF без админской сессии.
- Проверить сценарии отправки КП с PDF и предпросмотра письма.
- После публикации повторить запросы на production и убедиться по серверным логам, что каждый маршрут возвращает PDF со статусом 200 и больше не создаёт зависшие 502.

## Технические границы
- Без изменения бизнес-данных, структуры КП и базы данных.
- Генерация остаётся на `pdf-lib` с уже встроенными кириллическими шрифтами; сетевых загрузок ресурсов во время PDF-рендера не будет.
- Внешние технические детали не показываются пользователю, но сохраняются в серверных логах для диагностики.
