## Что меняем

Сейчас в `/admin/*`:
- сайдбар жёстко `w-64`, не сворачивается, на мобильных съедает экран;
- контент в `p-6`, без учёта узких ширин;
- в шапке нет никаких глобальных действий;
- много данных, которые уже есть в БД, в админке вообще не отображаются.

Делаем две вещи: (1) собственно адаптивный сворачиваемый сайдбар, (2) предлагаю список разделов, которые имеет смысл добавить, **строго из того, что уже есть в проекте** (таблицы, поля, маршруты) — без выдумок.

---

## 1. Сворачиваемый адаптивный сайдбар

### Каркас

`src/routes/admin.tsx` оборачиваем в `SidebarProvider`. Сам сайдбар — shadcn `Sidebar collapsible="icon"`:

- **Desktop**: разворачивается (`w-64`) ↔ сворачивается до иконок (`w-14`). Состояние хранится в cookie/localStorage самим `SidebarProvider`, не теряется между переходами.
- **Mobile (<768px)**: становится off-canvas drawer; кнопка-гамбургер в шапке.
- **Tablet (768–1024px)**: по умолчанию свернут в icon-режим.

### Шапка админки

В `admin.tsx` появляется sticky-хедер: слева `SidebarTrigger` (виден всегда, в т.ч. когда сайдбар свернут), посередине — хлебные крошки текущего раздела, справа — быстрые действия и `ThemeToggle` (он уже есть в проекте).

### Группировка пунктов

Сейчас 15 пунктов лежат плоским списком. Разбиваем на сворачиваемые `SidebarGroup`, активная группа автоматически раскрыта (по `pathname`):

- **Операции**: Дашборд, Заказы, Календарь, Занятость
- **Контент**: Наполнение, Кейсы, Отзывы, Блог
- **Маркетинг**: Маркетинг, Промокоды, Рассылка
- **Система**: Пользователи, Видимость секций, Аудит

В collapsed-режиме видны иконки, лейблы скрываются, тултип показывает название.

### Контент

`<div className="flex-1 min-w-0 p-4 md:p-6">` — убираем фикс p-6, чтобы редакторы (CRUD-таблица + форма справа) корректно ужимались на ≤1280px. Длинные строки в текстовых полях уже защищены `prose-wrap` из styles.css.

### Подвал сайдбара

Карточка с email текущего пользователя и кнопкой «Выйти» (используем существующий `useAuth`). В collapsed-режиме — только аватар-иконка.

## 2. Что добавить в админку (строго из существующего)

Это **не делаем сразу** — это перечень, из которого выбираете, что включать. Каждый пункт уже подкреплён реальными таблицами/функциями в проекте.

### Высокий приоритет — данные есть, UI нет

1. **Поддержка / чат** — таблицы `support_threads`, `support_messages` уже существуют (с telegram-интеграцией), но списка диалогов в админке нет. Раздел «Поддержка»: список тредов, переписка, ответ от админа.
2. **Логи писем** — `email_send_log`, `suppressed_emails`, `email_unsubscribe_tokens`. Раздел «Почта → Журнал»: статусы отправок, заблокированные адреса, отписки. Сейчас всё это только в БД.
3. **Логи Telegram** — `telegram_logs` уже пишутся, но просмотра нет. Простая таблица с фильтром по статусу + кнопка «повторить» (поле `retried_at` уже заложено).
4. **Брошенные корзины** — `cart_drafts` хранится, но не используется. Раздел: список пользователей с непустой корзиной, сумма, время последнего обновления, кнопка «Связаться» (email/телефон из `profiles`).
5. **Текстовые оверрайды** — `text_overrides` уже есть в схеме (path + original_text + override_text), но UI нет. Простой CRUD «Правки текстов на сайте».

### Средний приоритет — улучшения для существующего

6. **Бейджи новых заказов** в пункте «Заказы (CRM)» — счётчик `orders WHERE status='new'`. Используется тот же запрос, что уже есть на дашборде.
7. **Быстрое действие в шапке**: «+ Новый заказ» / «+ Позиция каталога» — дублирует существующие операции, но в один клик из любого раздела.
8. **Глобальный поиск (⌘K)** через `cmdk` (уже стоит как зависимость, на нём построен `CategoryCombobox`) — поиск по заказам (имя/email/телефон), позициям каталога, кейсам.
9. **Превью страницы перед публикацией** — на странице позиции каталога / кейса / блога кнопка «Открыть превью» с `published=false` (рендер уже умеет это через server fn для админа — нужно только пробросить флаг).

### Низкий приоритет — косметика/комфорт

10. **Хлебные крошки** в шапке: «Каталог / Зоны / [название]» — даёт быструю навигацию назад на 1 уровень.
11. **Sticky-action bar** в редакторе (`AdminEditorShell`): кнопки «Сохранить / Удалить / Опубликовать» прилипают к низу формы, чтобы не скроллить вверх на длинных описаниях.
12. **Памятка состояний заказа** — словарь `STATUS_LABEL` из `admin.index.tsx` использовать единым компонентом-чипом во всех таблицах (сейчас дублируется).
