# Раздел «Документы»: аудит и план улучшений

## Что сейчас есть (проверено по коду)

- `/admin/documents` — это просто редирект на список КП (`admin.documents.index.tsx`). Самого раздела как такового нет.
- Два почти одинаковых по смыслу модуля: **КП** (`documents/quotes/*`) и **КП‑промо** (`documents/promo/*`) — со своими таблицами, моделями, редакторами, версиями, шаблонами, сниппетами и своими HTML/PDF‑рендерами.
- **База знаний** (`documents/knowledge`) — контрагенты, позиции, тексты; наполняется автоматически, но на неё нет ссылок из редакторов.
- **Счёт, договор, акт** настраиваются в `/admin/settings/documents` (вкладки «Счёт», «Договор», «Акт»), но собственных экранов и списков не имеют: они генерируются «на лету» только с карточки заказа. Нет истории, статусов, номеров, версий, публичных ссылок.
- Публичная ссылка для клиента существует (`/kp/{token}`), но в интерфейсе её нельзя просто скопировать — только через отправку письма.

## Найденные проблемы

1. **Дублирование КП и КП‑промо.** Статусы, итоги, валидация, версии, шаблоны, отправка — реализованы дважды. Любая правка вёрстки/логотипа/НДС делается в двух местах, функции разъезжаются: XLSX‑экспорт и Undo есть только в промо, текстовые блоки и привязка к каталогу — только в обычном КП.
2. **Нет единой точки входа.** Пользователь не видит «Документы» как раздел: нет общего списка всех документов, нет счётчиков и статусов.
3. **Счета/акты/договоры «невидимы».** Настройки для них есть, а самих документов в системе нет — они не сохраняются и их нельзя найти позже.
4. **Разный уровень полировки.** В промо — `window.confirm` и `window.prompt`, в КП — нормальные диалоги. Разные подтверждения, разные тексты.
5. **Ручные шаги.** «Отметить отправленным» отдельно от реальной отправки; номер документа подтягивается вторым запросом; ссылку на клиента нельзя скопировать.
6. **Перегруженные экраны.** Редактор КП — 745 строк, ~30 полей в одном автосейве; настройки документов — 7 вкладок в одной форме; на списке КП три разных входа в создание.

## Предлагаемый план (по этапам)

### Этап 1. Каркас раздела и быстрые UX‑победы
- Сделать реальный экран `/admin/documents` — единый список **всех** документов (КП, КП‑промо, позже счета/акты/договоры) с фильтрами по типу, статусу, клиенту, дате и суммой; карточки‑счётчики сверху («черновики», «отправлено», «принято», «просрочено»).
- Один диалог создания документа: выбор типа → источник (с нуля / из заказа / из шаблона) вместо трёх кнопок.
- Кнопка «Скопировать ссылку для клиента» (`/kp/{token}`) рядом с «Отправить».
- Автоматически ставить статус «Отправлено» при реальной отправке письма; «Отметить вручную» оставить как вторичное действие для отправки вне системы.
- Заменить `window.confirm`/`prompt` в промо на общие `ConfirmDialog` и диалог названия шаблона.
- Undo/Redo и подсказки горячих клавиш — одинаково в обоих редакторах.
- Ссылка на базу знаний из редакторов (там, где работают автоподсказки).

### Этап 2. Унификация КП и КП‑промо
- Общий слой: статусы, расчёт итогов, валидация перед отправкой, версии, шаблоны, отправка, публичная ссылка — один модуль, промо остаётся «профилем» с доп. полями (множитель, комиссия, управление, исключение из комиссии).
- Единый рендер шапки/футера/реквизитов/НДС/логотипа для HTML и PDF, чтобы правка делалась один раз.
- Выровнять функциональность: XLSX‑экспорт и текстовые блоки доступны в обоих типах.
- Один редактор‑оболочка (левые вкладки + превью справа), различается только вкладка «Позиции».

### Этап 3. Счета, договоры, акты как полноценные документы
- Сохраняемые сущности со своими номерами, статусами (черновик / выставлен / оплачен / подписан / закрыт), суммами, привязкой к заказу и КП, версиями и PDF.
- Кнопка «Выставить счёт из КП/заказа» — автоматический перенос позиций, реквизитов и сумм.
- Отображение в общем списке документов и в карточке заказа (единая лента документов по сделке).

### Этап 4. Автоматизация и аналитика
- Автозаполнение реквизитов клиента из базы знаний по ИНН/названию при вводе.
- Напоминания: КП отправлено и не просмотрено N дней; срок действия истекает; счёт не оплачен.
- Статусы клиента (просмотрел / принял / отклонил с комментарием) видны прямо в списке.
- Мини‑аналитика: конверсия КП → заказ, средний чек, маржинальность по позициям.

## Техническая часть

- Новый общий модуль `src/lib/documents/core` — статусы, итоги, валидация, версии; `quotes-model.ts` и `promo-quote-model.ts` становятся тонкими профилями поверх него.
- Общий рендер‑слой: одна реализация header/party/items/summary/footer, используемая `quote-html.ts`, `promo-quote-html.ts` и `pdf.server.ts` (сейчас 63 КБ дублей).
- Новый экран‑агрегатор: серверная функция `listAllDocuments` c UNION‑выборкой по `quotes`, `promo_quotes` (позже `invoices`, `contracts`, `acts`).
- Для этапа 3 — миграции на таблицы `invoices` / `contracts` / `acts` c нумерацией через триггер (по образцу `set_quote_number`), GRANT + RLS для admin/manager.
- Редакторы разбиваются на секции‑компоненты, автосейв патчится по изменённым полям, номер документа возвращается ответом на сохранение (без второго запроса).

## Порядок

Рекомендую начать с Этапа 1 — он заметен администраторам сразу и не требует миграций. Этапы 2–4 можно делать по одному.
