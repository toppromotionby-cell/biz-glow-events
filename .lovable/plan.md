## Причина
В блоке «Наши рекомендации» (`FeaturedCard`) при автоскролинге переключаются все слайды, но видна только **первая фотка** — остальные навечно остаются пульсирующим скелетом.

Корень: в `src/lib/home.functions.ts` сервер подписывает (signed URL) только `photo_urls[0]` каждой карточки. Остальные фото остаются относительными путями к приватному bucket `media`. На клиенте `FeaturedCard → SlidePhoto → useResolvedUrl` пытается подписать их через `supabase.storage.createSignedUrl` от имени **anon**, но bucket приватный и anon не имеет права подписывать → возвращается `null` → слайд показывает placeholder.

В каталоге этой проблемы нет: `src/lib/catalog.functions.ts → signMediaUrls` подписывает все фото сразу (batch).

## Что меняется

### `src/lib/home.functions.ts`
Заменить блок, который подписывает только первое фото каждой карточки, на batch-подпись всех путей через один вызов `supabaseAdmin.storage.from("media").createSignedUrls(list, TTL)` — по образцу `signMediaUrls` из `catalog.functions.ts`:

- Собрать все относительные пути из `photo_urls` всех `featured` карточек в `Set`.
- Один батч-запрос `createSignedUrls` с TTL 7 дней (как в каталоге).
- Построить `Map<path, signedUrl>` и заменить относительные пути на подписанные во всех `photo_urls`.
- Абсолютные URL (`http(s):`, `blob:`, `data:`) пропускать.

## Что НЕ меняется
- Компоненты `FeaturedCard` / `SlidePhoto` — не трогаем.
- Каталог, авторизация, RLS — без изменений.
- Структура `HomeFeatured` остаётся той же.

## Проверка
После правки в карточке «Наши рекомендации» с несколькими фото при автоскролинге должны корректно появляться все фотки, без пульсирующего скелета на 2-й и последующих.
