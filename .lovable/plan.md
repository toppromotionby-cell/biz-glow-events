# План: устойчивые заголовки в карточках + защита от регрессий

## Цели
1. Минимизировать CLS на главной и в каталоге, который может возникать при подмене названий/обрезке во время гидрации и подгрузки.
2. Сделать обрезку названий «умной» — по словам, со стабильным многоточием во всех браузерах.
3. Зафиксировать поведение карточек скриншот-тестами, чтобы баг с градиентом/line-clamp не вернулся.
4. Привести `FeaturedCard` к виду, где `background-clip:text`, обрезка и hover-эффекты не конфликтуют ни при какой длине названия.

## Что меняем

### 1. Стабильная высота заголовка (нулевой CLS)
- `<h3>` в `FeaturedCard` и `CatalogCard` получает фиксированный резерв высоты ровно под 2 строки на каждом брейкпойнте через `min-h-[2lh]` (с фолбэком на `min-height: calc(line-height * 2)` для старого Safari).
- Контейнер описания уже имеет min-height — выровняю значения с реальной высотой при `line-clamp-2/3`, чтобы при переключении «1 строка → 2 строки» (после ресайза/смены данных) не было прыжка.
- Сетка рекомендаций (`src/routes/index.tsx`) и `CatalogGrid` дополнительно получают `grid-auto-rows: 1fr`, чтобы карточки в ряду имели одинаковую высоту независимо от длины заголовка.

### 2. Умная обрезка по словам с устойчивым `…`
- Новый утильный компонент `ClampedTitle` (`src/components/ui/ClampedTitle.tsx`):
  - использует CSS `line-clamp-2` как первичный механизм (работает в Chromium/WebKit с настоящим многоточием);
  - в `ResizeObserver` после рендера измеряет, помещается ли текст; если строк больше двух — обрезает на границе слова и дописывает `…` (фолбэк для Firefox и для случаев, где CSS-обрезка дала «грязный» край);
  - не вставляет точки в середину слова, не оставляет «висячие» предлоги/союзы (`в`, `и`, `на`, `с`, `по`, `от`, `для`) в конце — отбрасывает их вместе с предыдущим словом;
  - сохраняет полный текст в `title=` и `aria-label`, чтобы доступность не страдала.
- Текст рендерится в одном элементе, на котором одновременно живут `card-title-gradient` и `line-clamp-2`, — это уже починено, но теперь оборачивается в `ClampedTitle`, чтобы не дублировать логику.

### 3. Защита от рассинхрона hover/градиента
- `FeaturedCard`: hover-усиление свечения и подчёркивающая полоска вынесены в `:where(...)`-селектор, чтобы не повышать специфичность над `card-title-gradient` и не «перебивать» градиент при наведении.
- Добавлю явный `will-change: filter` только на hover (через `group-hover:will-change-[filter]`), чтобы избежать «моргания» текста в Safari, когда меняется `drop-shadow`.
- Уберу `transition` с самого градиента (он не нужен, переходит только `filter`).
- Изоляция: контейнер карточки получает `isolation: isolate` — это предотвращает редкие баги, когда `background-clip: text` пересекается с родительскими blur/backdrop-фильтрами.

### 4. Визуальные регрессионные тесты
Новый файл `tests/visual/cards.spec.ts` использует уже настроенный `playwright.config.ts` (375/414/640/768/1024). Для каждого вьюпорта снимает скриншоты:
- одной карточки `FeaturedCard` на главной с реальным коротким названием;
- той же карточки с принудительно длинным названием (инжектится через `page.evaluate`) — проверяем обрезку и градиент;
- одной карточки `CatalogCard` в каталоге с коротким и длинным названием;
- состояние при hover на десктопных вьюпортах (`page.hover` + ждать конца перехода);
- skeleton-плейсхолдера до загрузки изображений (отключение картинок через `page.route`).

Стабилизация (как в `centering.spec.ts`): отключаем анимации/переходы, скрываем `img/video`, ждём `document.fonts.ready`, имитируем `prefers-reduced-motion`. Снапшоты складываются per-project — регрессия на одном вьюпорте не валит остальные.

Команда обновления: `bunx playwright test tests/visual/cards.spec.ts --update-snapshots`.

В README визуальных тестов добавлю короткую секцию «Cards» с тем, что покрыто и как обновлять снапшоты.

### 5. Микро-фиксы CLS вне заголовка
- В `FeaturedCard` slide-индикаторы (точки) уже абсолютные — ок.
- Блок цены: проверю, что `PriceBlock` всегда возвращает элемент одной высоты («Цена по запросу» vs «от N BYN»); если высоты различаются, выровняю через `min-h`.
- Дескриптор: уже есть `min-h-[2.25rem] sm:min-h-[3.75rem]`, но при отсутствии описания рендерится `\u00A0` — оставлю, это правильное поведение.

## Технические заметки
- `min-h-[2lh]` поддерживается Chrome 110+, Safari 16.4+, Firefox 120+. Для старых браузеров есть автоматический фолбэк через классический `min-height` в `px`, рассчитанный по `line-height`.
- `ResizeObserver` + измерение текста делаем один раз после layout (`useLayoutEffect`), чтобы избежать flash; повторный замер только при изменении ширины контейнера.
- В тестах принудительно длинный заголовок инжектится через `page.evaluate`, чтобы покрыть пограничный случай без зависимости от данных в БД.
- Все изменения остаются во фронтенде; данные/серверные функции не трогаем.
