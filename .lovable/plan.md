# Починка кнопки PDF (ошибка 502)

## Что происходит

Кнопка «PDF» в разделе Документы иногда отдаёт «Не удалось получить файл (502): Internal server error». В логах продакшена видно: часть запросов `/admin/documents/quotes/<id>/render?format=pdf` возвращает 200, а часть падает с ошибкой рантайма — «Worker's code had hung and would never generate a response».

Причина: перед сборкой PDF сервер по сети скачивает два TTF-шрифта (Roboto Regular и Bold, ~500 КБ каждый) с публичного адреса самого же проекта. Это запрос воркера «сам к себе»: он то проходит, то зависает, и тогда запрос убивается по таймауту — отсюда плавающий 502. Промо-КП использует тот же генератор, поэтому проблема общая для обоих модулей.

## Что сделаю

1. Уберу скачивание шрифтов во время запроса — шрифты будут вшиты прямо в код.
   - Урежу Roboto Regular/Bold до нужных наборов символов (кириллица, латиница, цифры, пунктуация, ₽/€/№) — вместо ~500 КБ получится примерно 60–90 КБ на начертание.
   - Сохраню их как модули с base64-данными и буду декодировать в памяти при первой генерации PDF.
2. Добавлю защиту от зависания: если что-то со шрифтом пойдёт не так, генерация не виснет, а падает быстро и понятно.
3. Ошибки рендера буду возвращать как читаемое сообщение и писать в лог, чтобы вместо «Internal server error» было видно причину.
4. Проверю оба маршрута — обычное КП и КП Промо, в форматах PDF и HTML, включая кириллические названия файлов.

## Технические детали

- `src/lib/documents/pdf.server.ts`: удалить `fetchFont`/`ASSET_HOST`/URL-константы, читать байты из новых модулей `src/assets/fonts/roboto-regular.base64.ts` и `roboto-bold.base64.ts` (генерация сабсетов через `fonttools pyftsubset`, запуск разово при разработке; в репозиторий попадают только готовые base64-модули).
- Кеш `regularBytesPromise` / `boldBytesPromise` заменить на синхронную ленивую декодировку base64 → `Uint8Array` (без сетевых промисов, которые могут «залипнуть» между запросами воркера).
- `src/routes/admin.documents.quotes.$id.render.tsx` и `src/routes/admin.documents.promo.$id.render.tsx`: обернуть построение PDF в try/catch, при ошибке — `500` с текстом ошибки и `console.error` с id документа.
- Проверка: локальный запрос обоих render-эндпоинтов, валидация полученного PDF (число страниц, наличие кириллицы), затем прогон через браузер по кнопке «PDF».
