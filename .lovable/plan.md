# КП и КП Промо: удобство и недостающие функции

Цель — довести оба модуля до состояния «открыл, собрал, отправил клиенту, увидел реакцию» без лишних кликов и без знания внутренностей.

## 1. Отправка клиенту (главный пробел)

Сейчас документ можно только скачать вручную. Добавляем:

- **Публичная ссылка на КП.** Страница `/kp/<токен>` — фирменная веб-версия предложения с кнопкой «Скачать PDF». Токен уже есть в базе у обычного КП; для промо-КП добавим такой же.
- **Кнопки «Скопировать ссылку» и «Открыть как клиент»** в шапке редактора и в списке.
- **Отправка на e-mail** прямо из редактора: письмо клиенту со ссылкой и вложенным PDF, адрес подставляется из карточки. Факт отправки пишется в документ (дата, кому).
- **Реакция клиента.** На публичной странице кнопки «Согласовать» / «Отказаться» с комментарием; статус КП меняется автоматически, менеджер видит отметку «просмотрено клиентом» и дату.

## 2. Срок действия и напоминания

- Явное поле «действительно до» с подсветкой: скоро истекает / просрочено.
- В списке — фильтр «Требует внимания» (отправлено больше N дней назад и без ответа).

## 3. Быстрый старт документа

- **Мастер создания** в одном окне: с нуля / из шаблона / из заказа / копия существующего — сейчас это разные кнопки и диалоги.
- Пресеты состава: типовые наборы позиций добавляются одним кликом.
- Для промо-КП — кнопка «Дублировать» прямо в списке (сейчас есть только внутри диалога создания).

## 4. Удобство редактора (оба модуля)

- **Единая шапка**: номер, статус, сумма, автосохранение, действия (PDF, ссылка, отправить, версия, ещё) — одинаково в КП и в Промо.
- **Горячие клавиши**: Ctrl+S — сохранить, Ctrl+D — дублировать позицию, Ctrl+Enter — добавить позицию, Esc — закрыть диалоги; подсказка по «?».
- **Массовые действия по позициям**: выделение чекбоксами, перенос в другой раздел, удаление, изменение цены/наценки для группы.
- **Свернуть/развернуть разделы**, счётчик позиций и сумма по каждому разделу.
- **Отмена последнего действия** в обычном КП (в промо уже есть) + «Восстановить удалённую позицию».
- **Превью**: переключатель «Как видит клиент» / «Внутренний вид» (себестоимость и маржа скрываются), масштаб превью, кнопка «Обновить».
- **Понятные ошибки**: блок предполётных проверок остаётся, но каждая строка кликабельна и ведёт к проблемному полю.

## 5. Единый список документов

- Общая страница «Документы» со сводкой: черновики, отправленные, согласованные, сумма в работе.
- В таблицах — колонки «Клиент», «Сумма», «Действителен до», «Просмотрено», быстрые действия (ссылка, PDF, копия, удалить), сортировка по сумме и дате.

## 6. Связь с заказом

- Кнопка «Создать заказ из КП» после согласования: позиции, клиент и суммы переносятся в новый заказ.
- В карточке заказа — список связанных КП.

## Технические детали

- БД: `promo_quotes` — добавить `public_token`, `viewed_at`, `client_response`, `client_comment`, `valid_until` (для quotes — недостающие поля `viewed_at`, `client_response`, `client_comment`); отдельные политики не нужны, публичный доступ идёт через серверную функцию по токену (RLS не открываем).
- Публичные маршруты: `src/routes/kp.$token.tsx` (обычное КП) и `src/routes/kp.promo.$token.tsx`, данные — через server fn с `supabaseAdmin` и проверкой токена; отдача PDF — существующие render-роуты в режиме токена.
- Отправка письма — через существующий email-слой проекта (шаблон `quote_sent`), без новых внешних сервисов.
- Общая шапка редактора выносится в `src/components/admin/documents/DocumentHeader.tsx`, массовые действия — в `QuoteItemsPanel` / `PromoItemsTable`.
- Фирменный стиль: акцент `#FF7500`, без фиолетового; публичная страница КП использует те же токены, что и сайт.

## Порядок работ

1. БД-миграция и серверные функции публичного доступа.
2. Публичные страницы КП + кнопки ссылки/копирования.
3. Отправка на e-mail и реакция клиента (статусы, просмотры).
4. Общая шапка, горячие клавиши, массовые действия, превью-режимы.
5. Список документов со сводкой и фильтром «требует внимания».
6. Создание заказа из КП.
