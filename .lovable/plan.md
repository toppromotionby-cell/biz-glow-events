# Корректное превью и скачивание PDF

## Что подтверждено

- PDF сейчас передаётся в браузер как `blob:` URL и вставляется напрямую в `<iframe>`. В окне Lovable это получается вложенный PDF-viewer внутри sandbox-iframe; на скриншоте он не отрисовал страницы и показал пустой лист.
- Кнопка «Скачать» создаёт ссылку с `download`, а затем внутри iframe дополнительно вызывает `window.open`. Оба действия могут быть проигнорированы или заблокированы ограничениями вложенного окна.
- Сервер уже возвращает PDF с типом `application/pdf`, UTF-8 именем и единым обработчиком ошибок. Текущий регрессионный тест проверяет только заголовки и строку `%PDF`, но не валидность сгенерированного документа и не пользовательский сценарий скачивания.

## План исправления

1. **Заменить встроенный браузерный PDF-viewer на управляемое превью**
   - Для PDF отрисовывать страницы внутри диалога через браузерную PDF-библиотеку, а не вставлять `blob:` в iframe.
   - Добавить состояния загрузки/ошибки, прокрутку многостраничного документа и адаптивное масштабирование без пустого белого экрана.
   - HTML-документы оставить в изолированном iframe, поскольку проблема относится к PDF.

2. **Разделить просмотр и реальное скачивание**
   - Сохранять исходный `Blob` документа в провайдере просмотрщика, а не только временный URL.
   - Кнопкой «Скачать» создавать свежий объектный URL и нативную ссылку загрузки непосредственно из клика пользователя; имя брать из `Content-Disposition`.
   - Не открывать вторую вкладку автоматически. «В новой вкладке» оставить отдельным явным действием с понятным fallback, если среда блокирует blob-навигацию.
   - Применить тот же надёжный helper к PDF из КП, КП Промо, заказов и прикреплённых файлов.

3. **Усилить проверку ответа перед показом**
   - Проверять `Content-Type`, непустой размер и PDF-сигнатуру до открытия диалога, чтобы JSON/HTML ошибки не выглядели как пустой PDF.
   - Для некорректного ответа показывать понятное сообщение с диагностическим ID, если он пришёл от сервера.

4. **Добавить регрессионные проверки**
   - Unit-тесты для определения PDF, имени файла, создания/освобождения object URL и fallback ошибок.
   - Проверка, что реальные генераторы КП, КП Промо и документов заказа создают читаемый PDF минимум с одной страницей.
   - Browser-тест: открыть PDF в разделе «Документы», дождаться видимой первой страницы, нажать «Скачать» и подтвердить событие загрузки с корректным `.pdf` именем.

## Технические детали

- Использовать клиентскую PDF.js-совместимую библиотеку с worker-файлом, подключённым способом, безопасным для TanStack Start SSR.
- Не менять структуру и дизайн самих коммерческих предложений; исправление касается только доставки, превью и скачивания файлов.
- После реализации проверить обычный браузер и вложенное окно Lovable на desktop-размере из скриншота.
