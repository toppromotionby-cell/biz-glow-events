
## Цель

Чётко разделить два сценария:
- **Заказ** — клиент уже выбрал позиции в корзине и хочет оформить.
- **Запрос (inquiry)** — клиент не готов заказать, ему нужна консультация / уточнение.

Сейчас обе ветки идут в `orders` одинаково, и менеджеру тяжело отличить «надо звонить и выяснять» от «надо подтверждать готовый заказ».

## Что меняется для пользователя

### Публичная часть
- **Корзина (`/cart`)** — остаётся как есть, шаг «Оформить заказ» (с позициями, суммой, реквизитами).
- **Контакты / `LeadForm` / `QuickQuoteForm` / попапы** — становятся формой **«Оставить запрос»**: имя, телефон, email, дата (необяз.), сообщение. Без позиций и сумм. Заголовок и CTA: «Свяжитесь со мной», подсказка: «Менеджер свяжется и поможет подобрать».
- На карточках каталога рядом с «В корзину» появляется второстепенная ссылка **«Задать вопрос»** — открывает ту же форму запроса с предзаполненным `subject`.
- После отправки запроса клиент получает письмо **«Мы получили ваш запрос»** + короткую анкету уточнений (дата, кол-во гостей, формат, бюджет, площадка) — ссылка ведёт на новую страницу `/inquiry/{token}` с формой, ответ дописывается в `order.notes` и тайм-лайн.

### Админка
- Новый статус заказа `inquiry` (расширение enum `order_status`).
- В `/admin/orders` — фильтр-вкладки сверху: **Все / Заказы / Запросы** (запросы = `status='inquiry'`).
- В сайдбаре у пункта «Заказы» — **бейдж со счётчиком непрочитанных запросов** (новых `inquiry` без действий в timeline).
- В карточке/диалоге заказа-запроса:
  - яркий бейдж **«ЗАПРОС — связаться с клиентом»**;
  - блок «Ответы клиента из анкеты» (если заполнил);
  - кнопка **«Превратить в заказ»** — переводит в `new`, открывает редактор позиций;
  - кнопки КП/Счёт/Договор/Акт **скрыты**, пока статус `inquiry` (нечего выставлять).

### Уведомления
- Telegram + email админу с темой **«🟡 ЗАПРОС от {имя}»** (отдельно от «🟢 Новый заказ»), шаблон отличается визуально и текстом «требуется связаться и уточнить».
- В `/admin/notifications` событие `inquiry_created` в тайм-лайне и в фильтре шаблонов письма.

## Технический раздел

### 1. БД (миграция)
- `ALTER TYPE order_status ADD VALUE 'inquiry' BEFORE 'new';` (если допускается порядок — иначе просто ADD VALUE).
- В `orders` уже есть `source`, `notes` — новых колонок не нужно. Доп. поле `kind text generated…` не вводим, разделение через `status`.
- Таблица `inquiry_clarifications` (`id`, `order_id` FK, `token` unique, `event_format`, `guests_count`, `budget`, `venue`, `extra`, `answered_at`). GRANT `service_role` + RLS: чтение/запись только через server fn по токену.

### 2. Серверные функции
- `submitInquiry` (новая, в `src/lib/leads.functions.ts` или новый `inquiries.functions.ts`):
  - схема без позиций/сумм/реквизитов;
  - создаёт `orders` со `status='inquiry'`, `source='inquiry'`;
  - генерирует `clarification_token`, шлёт клиенту письмо **`client-inquiry-received`** со ссылкой `/inquiry/{token}`;
  - шлёт Telegram + админ-email шаблон **`admin-inquiry`** (отличный от `admin-order`);
  - пишет timeline `inquiry_created`.
- `submitInquiryClarification` — публичная по токену, апдейтит `inquiry_clarifications`, пишет timeline `inquiry_clarified`.
- `promoteInquiryToOrder` (admin, `requireSupabaseAuth` + `has_role staff`): меняет `status` → `new`, timeline `inquiry_promoted`.
- `submitOrder` (существующая) — добавить guard: позиции обязательны (если пусто — кидать понятную ошибку, не превращать в `inquiry` молча).
- Обновить `sendOrderConfirmationEmailAndLog`: для `status='inquiry'` НЕ генерировать КП/Счёт/Договор/Акт.

### 3. Email-шаблоны (React Email, `src/lib/email-templates/`)
- `admin-inquiry.tsx` — жёлтый акцент, «Новый запрос на консультацию», контакты, сообщение, кнопка «Открыть в админке».
- `client-inquiry-received.tsx` — «Спасибо, мы свяжемся», кнопка «Уточнить детали» → `/inquiry/{token}`.
- Зарегистрировать в `registry.ts`.
- Сабжекты: `[ЗАПРОС] …` чтобы визуально отличался в инбоксе.

### 4. UI
- Новый компонент `InquiryForm` (на базе `LeadForm`, без даты как обязательной, с поясняющим текстом).
- `LeadForm`/`QuickQuoteForm`/попапы — заменить вызов `submitLead` → `submitInquiry` (и переименовать визуально). Старый `submitLead` оставить как алиас для обратной совместимости либо удалить с фолбэком (см. ниже).
- В карточках каталога (`CatalogDetail`, `AddToCartButton` соседство) — линк «Задать вопрос», открывает модалку с `InquiryForm`.
- `/admin/orders`: вкладки фильтра, бейдж статуса «Запрос», скрытие кнопок документов.
- `AdminSidebar`: подгрузка count(`status='inquiry'` за 7 дней) через server fn, бейдж.
- Новая страница `/inquiry/$token` — публичная, форма уточнений.

### 5. Совместимость
- Существующие записи `orders` с `source='website'/'contacts'` и без позиций НЕ переразмечаются автоматически (избегаем сюрпризов в отчётах). В админке — баннер «Старые лиды можно вручную пометить как запросы» (кнопка batch — опционально, по запросу).

### 6. Тестирование
- `tsc --noEmit`.
- Playwright: отправка `InquiryForm` → проверка письма в `email_send_log` (template=`client-inquiry-received`, `admin-inquiry`), запись `orders.status='inquiry'`, событие `inquiry_created` в `/admin/notifications`, бейдж в сайдбаре.
- Проверка: для inquiry-заказа в OrderDialog нет кнопок КП/Счёт/Договор/Акт; после `promoteInquiryToOrder` — появляются.

## Вне scope
- Массовая миграция старых лидов в `inquiry`.
- Чат-виджет / онлайн-консультант.
- Автоматическая выдача КП по ответам анкеты (это следующий шаг).
