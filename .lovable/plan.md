# Ошибка «Invalid enum value ... received 'emerald'» + фон слайдов

## Откуда ошибка

В текущем коде список шаблонов презентации — 7 значений (`light, dark, accent, night, sunset, emerald, glow`) в `src/lib/presentations/model.ts`, и все серверные валидаторы ссылаются именно на него. Ошибка в скриншоте перечисляет только три старых варианта (`light | dark | accent`), значит её выдаёт сборка, собранная до расширения списка — то есть опубликованная версия сайта, а не текущий превью-код. В базе ограничения на колонку `template` нет (проверено), так что данные не пострадали.

Влияние: на опубликованном домене любое сохранение презентации с «новым» шаблоном падает с красным тостом и изменения не записываются; в редакторе превью — работает.

## Что делаю

1. **Устойчивость вместо жёсткой ошибки.** Валидаторы шаблона на сервере перестают ронять запрос на незнакомом значении: неизвестный шаблон нормализуется в безопасный дефолт (как уже делает `normalizePresentation`). Так рассинхрон клиента и сервера больше никогда не блокирует сохранение.
2. **Сквозная проверка списка шаблонов.** Один источник правды используется во всех точках: создание, обновление, дублирование, снапшоты, публичная ссылка `/p/<token>`, PDF, миниатюры, полноэкранный режим. Тест паритета расширяю, чтобы он ловил любое место с захардкоженным списком.
3. **Переиздание сайта** после правок, чтобы прод перестал работать на старой схеме.

## Тёмная тема = чёрный фон

Сейчас шаблон «Тёмный» — тёмно-серый `#0f1115`. Делаю настоящий чёрный фон с аккуратными производными токенами (панели, линии, приглушённый текст), чтобы контраст оставался читаемым, а не «выжженным».

## Свой фон на любом слайде

- В панели настроек слайда появляется блок **Фон**: «Как в шаблоне» (по умолчанию) / сплошной цвет / градиент из двух цветов, плюс палитра готовых фонов из стилистики сайта (тёмные, светлые, акцентные).
- Работает на всех типах слайдов, включая шаблонные (титульный, раздел, товар, текст, контакты).
- Переопределение хранится в контенте слайда, поэтому миграция БД не нужна; старые слайды продолжают наследовать тему презентации.

## Автоподбор цветов текста

При смене фона остальные цвета не задаются вручную — они вычисляются:
- считается яркость фона (по среднему по стопам градиента);
- текст, подзаголовки, линии, панели и «плашки» берутся из светлого или тёмного набора токенов сайта, с проверкой контраста (не ниже комфортного порога);
- акцент остаётся фирменным, но при плохом контрасте на конкретном фоне подменяется на читаемый вариант из той же палитры.

Одинаковая логика применяется в трёх местах, чтобы редактор, публичная ссылка и PDF выглядели идентично: HTML-превью (`SlideCanvas`), рендер по токену и генератор PDF.

## Технические детали

- `src/lib/presentations/design.ts` — `slideTheme` принимает фон-оверрайд слайда; новая функция `themeFromBackground(stops, angle, accent)` с расчётом яркости/контраста.
- `src/lib/presentations/model.ts` — поле `background` в `SlideContent` (`{ mode, stops, angle }`) + нормализация.
- `src/lib/presentations/pdf.server.ts` и `render.server.ts` — используют тот же вычисленный набор токенов, включая градиентную заливку слайда.
- `src/components/admin/presentations/SlideSettingsPanel.tsx` — UI выбора фона; `SlideCanvas.tsx`, `SlideThumbRail.tsx`, `PresentationFullscreen.tsx` — рендер с учётом оверрайда.
- Тесты: контраст токенов для набора фонов, паритет списка шаблонов, снапшот геометрии PDF (существующие 240 тестов должны остаться зелёными).
