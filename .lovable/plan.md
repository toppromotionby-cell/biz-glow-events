## Задача
1. При добавлении товара из каталога (кнопка «В корзину», быстрый просмотр, кросс-селл, вишлист, «повторить заказ») — в корзину должна попадать **ровно 1 единица**, повторные клики не должны бесконтрольно увеличивать qty.
2. В самой корзине у каждого товара должен быть **разумный лимит** количества (не 99 «в потолок»), с учётом типа сущности и единицы измерения.

## Правила лимитов
Единый хелпер `maxQtyForItem(entity_type, unit)` в `src/lib/pricing.ts`:

| Категория / единица | Мин | Макс |
|---|---|---|
| `zones` (площадка/фотозона) | 1 | **1** |
| unit = час | 1 | 24 |
| unit = день/сутки | 1 | 14 |
| unit = человек | 1 | 500 |
| `services` (шт./без единицы) | 1 | 10 |
| `tech_equipment` (шт.) | 1 | 50 |
| `production_items` (шт.) | 1 | 100 |
| фолбэк | 1 | 20 |

## Изменения

### `src/lib/pricing.ts`
- Добавить `maxQtyForItem(entity_type: CartEntityType, unit?: string | null): number` — заменяет текущий `maxQtyFor(kind)` в контексте корзины (старый оставить, используется в HourPriceSlider).

### `src/lib/cart.ts`
- В `CartItem` добавить необязательное поле `unit?: string | null` — чтобы в корзине знать «час/шт./день» без похода в БД.
- `addToCart(it)`: если позиция **уже есть в корзине** — НЕ инкрементировать qty; вместо этого вернуть флаг `{ added: false, alreadyInCart: true }`. Явный `updateQty` — единственный способ поднять количество. Это решает «сколько угодно» при повторных кликах и в кросс-сейле/вишлисте.
- `updateQty(...)` уже клампит снизу, добавить верхний клэмп по `maxQtyForItem`.

### Места добавления в корзину
Пробрасывать `unit` в `addToCart({... unit: it.unit_of_measure ?? null})`:
- `src/components/AddToCartButton.tsx` — принять проп `unit`.
- `src/components/CatalogDetail.tsx`, `CatalogQuickView.tsx`, `CartCrossSell.tsx`, `src/routes/wishlist.tsx` — передать `unit`.
- `src/routes/profile.tsx` (повтор заказа) — при клампе qty ограничить сверху `maxQtyForItem`.

Тосты (`AddToCartButton`, вишлист, кросс-селл): если `alreadyInCart` — показывать «Уже в корзине — измените количество там» вместо повторного `+1`.

### Корзина
- `src/components/cart/CartItemsPanel.tsx`: при рендере `<QtyStepper>` вычислять `max = maxQtyForItem(i.entity_type, i.unit)` и передавать в `max`. Для `zones` степпер фактически залочен на 1 (min=max=1) — можно скрыть кнопки и показать бейдж «1 площадка».
- `src/components/ui/QtyStepper.tsx`: без изменений (уже поддерживает max), только дефолт снизить с 99 до 20.

### Что НЕ трогаем
- Админка, БД, серверные функции, документы, письма — лимиты сугубо клиентские (UX-ограничение корзины). Бэкенд остаётся источником истины по доступности.
- `HourPriceSlider` и часовой калькулятор на детальной — там своя логика часов, не корзинная.

## Проверка
- Кликнуть «В корзину» на карточке зоны 3 раза → в корзине 1 позиция qty=1, второй клик → тост «уже в корзине» (кнопка и так превращается в «В корзине», это подстраховка для кросс-селла/вишлиста).
- Открыть корзину для zones → степпер недоступен/скрыт, qty=1.
- Для tech_equipment степпер уходит максимум до 50, дальше «+» задизейблен.
- Повтор заказа из профиля с qty=999 → в корзине клампится по лимиту.
