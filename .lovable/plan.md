# Ошибка «Формат ЧЧ:ММ» в редакторе КП

## Что происходит

В карточке КП поля «Время начала» и «Время окончания» — обычные текстовые поля, а сохранение срабатывает автоматически через 1,2 секунды после ввода. Пока вы допечатываете «1», «18», «18:0», автосохранение уже уходит на сервер, там проверка требует полный формат ЧЧ:ММ и возвращает отказ. Вместо человеческого текста на экран выводится сырой технический ответ:
`[ { "code": "custom", "message": "Формат ЧЧ:ММ", "path": [ "patch", "event_time_end" ] } ]`.

То же самое возможно и с другими полями: дата документа (при вводе года «2», «20»), e-mail, — любое поле со строгой проверкой ломает автосохранение на промежуточном значении.

## Что сделаем

1. Поля времени — нормальный ввод времени: маска/тип `time` с шагом 5 минут и подсказкой. Значения вроде `18:00:00` (приходящие из заказа) автоматически приводятся к `18:00`, «1800» и «18.00» — к `18:00`.
2. Автосохранение перестаёт отправлять заведомо неполные значения: неполное время/дата не уходят на сервер, поле подсвечивается как «допишите значение», а сохранение проходит по всем остальным полям.
3. Сообщения об ошибках — человеческие. Любой технический JSON от проверки превращается в короткий текст вида «Время окончания: укажите в формате ЧЧ:ММ» с указанием поля; сырой JSON больше нигде не показывается.
4. Проверка всех связанных мест: те же правки применяем к КП Промо и к остальным полям со строгой проверкой (дата документа, e-mail, УНП, числа), чтобы автосохранение не падало на промежуточном вводе.
5. Прогон в браузере: открыть КП и КП Промо, ввести время по символам, проверить, что ошибка не появляется, документ сохраняется, а PDF/предпросмотр показывают время корректно.

## Технические детали

- `src/lib/quotes-model.ts`: добавить `normalizeTime()` (обрезка секунд, `HHMM`/`HH.MM` → `HH:MM`), применить в `normalizeQuote` и в `quotePatchSchema` через `preprocess`; сообщения ошибок сделать с именем поля.
- `src/routes/admin.documents.quotes.$id.index.tsx`: поля времени — `<Input type="time">` (fallback — маска), в блоке автосохранения фильтровать поля, не прошедшие локальную проверку (`quotePatchSchema.partial().safeParse`), и не отправлять их.
- Новый хелпер `src/lib/admin/zod-message.ts`: `friendlyZodMessage(err)` — из `ZodError`/JSON-строки в «Поле: сообщение»; использовать в `SaveStatus` и `toast.error` редакторов КП и Промо.
- `src/routes/admin.documents.promo.$id.index.tsx` + `src/lib/promo-quote-model.ts`: та же нормализация и фильтрация перед автосохранением.
- Проверка: `tsgo --noEmit`, `vitest run`, Playwright-прогон обоих редакторов с чтением консоли.
