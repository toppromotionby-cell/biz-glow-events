# Роли в админке: убрать маркетолога, добавить бухгалтера, включить реальные ограничения

## Что сейчас

- Роли: `admin`, `manager`, `content_editor`, `marketer`. Ни у одного пользователя роли «маркетолог» нет (в базе только 2 админа и 1 контент-редактор), так что удаление безопасно.
- Проверка доступа сейчас «всё или ничего»: любой сотрудник (staff) попадает во все разделы админки — сайдбар не фильтруется по роли, серверные функции проверяют только «является ли сотрудником».
- Роли пользователя кешируются на 60 секунд, поэтому после смены роли интерфейс обновляется не сразу.
- На маркетолога завязаны две политики доступа в базе (рассылки и маркетинговые логи) — их надо переписать.

## Итоговая модель ролей

| Раздел | Админ | Менеджер | Бухгалтер | Контент-редактор |
|---|---|---|---|---|
| Дашборд | да | да (по своим заказам) | суммы и оплаты | нет |
| Заказы (CRM) и запросы | все | только где он ответственный | все, только чтение + отметка оплаты | нет |
| Календарь | да | свои заказы | нет | нет |
| КП и промо-КП | да | да, **без себестоимости и маржи** | чтение | нет |
| Счета, договоры, акты | да | создание по своим заказам | полный доступ | нет |
| Реквизиты и шаблоны документов | да | нет | да | нет |
| База знаний документов | да | да | да | нет |
| Каталог, кейсы, отзывы, блог, разделы | да | нет | нет | да |
| Рассылки, промокоды, почтовые ящики | да | да | нет | нет |
| Пользователи, аудит, уведомления, шаблоны писем, соцсети, видимость секций | да | нет | нет | нет |

Менеджер не видит: чужие заказы, себестоимость и маржу, системные разделы.

## Что делаем

1. **Убираем маркетолога.** Роль исчезает из выпадающих списков, подписей и всех проверок доступа. Политики базы для рассылок и маркетинговых логов переводятся на админа и менеджера.
2. **Добавляем бухгалтера** (`accountant`) — финансовый блок: документы, счета, акты, оплаты, реквизиты; без каталога и без системных настроек.
3. **Смена роли применяется сразу.** После изменения роли в разделе «Пользователи» права пересчитываются без перезагрузки: подписка на изменения ролей, сброс кеша, повторная проверка доступа к текущей странице. Если у пользователя отобрали доступ к разделу, его перебрасывает на доступную страницу с понятным сообщением.
4. **Сайдбар и страницы фильтруются по роли** — человек видит только свои разделы, а не пустые «нет доступа».
5. **Ограничения дублируются на сервере** — скрытие пунктов меню не защищает данные, поэтому каждая серверная операция проверяет конкретное право, а не «сотрудник/не сотрудник».
6. **Скрытие себестоимости и маржи** для менеджера: в редакторе КП и промо-КП колонки закупки/маржи не отображаются и не приходят с сервера.
7. **Страница «Пользователи»** получает описание каждой роли и матрицу прав, чтобы было понятно, что открывает роль стороннему человеку.

## Технические детали

- Миграция: добавить значение `accountant` в enum `app_role`; переписать политики `Marketers manage campaigns` и `Marketers read logs` на `has_role(admin) or has_role(manager)`; удалить строки роли `marketer` из `user_roles` (их нет, но чистим на всякий случай). Значение enum `marketer` физически остаётся (Postgres не удаляет значения enum безопасно), но полностью выводится из кода и политик.
- Новый модуль `src/lib/permissions.ts`: список прав (`orders.view_all`, `orders.manage`, `documents.finance`, `documents.cost_margin`, `content.manage`, `marketing.manage`, `system.manage`, `users.manage`, `audit.view`) и матрица «роль → права», общая для клиента и сервера.
- `src/hooks/use-roles.ts`: `staleTime: 0`, realtime-подписка на `user_roles` по своему `user_id` с инвалидацией запроса и `router.invalidate()`; экспорт `can(permission)`.
- `src/components/admin/AdminSidebar.tsx`: у каждого пункта поле `perm`, группы скрываются целиком, если нет ни одного доступного пункта.
- `src/routes/admin.tsx`: гейт по «есть хоть одно право админки»; каждый маршрут админки получает проверку своего права с редиректом на первый доступный раздел.
- Серверные функции: единый помощник `assertPermission(context, perm)` вместо разрозненных `assertStaff` в `orders/quotes/promo-quotes/finance-documents/campaigns/email-templates/site-settings/catalog-*`. В `orders.functions.ts` для менеджера добавляется фильтр `manager_id = userId`; в `quotes/promo-quotes` поля `cost` и производные по марже вырезаются из ответа без права `documents.cost_margin`.
- UI КП: `QuoteItemsPanel`, промо-аналог и сводки по марже рендерят колонки закупки только при наличии права.

## Проверка

- Тестовые аккаунты на каждую роль: вход, состав меню, попытка открыть закрытый URL напрямую, прямой вызов серверной операции.
- Смена роли админом в другом окне — интерфейс второго пользователя перестраивается без перезагрузки.
- Менеджер видит только свои заказы и КП без закупочных цен.
