# Аккуратный столбец «Количество» во всех КП (кроме КП Промо)

Цель: колонка количества везде выглядит одинаково и опрятно — фиксированная ширина, значение по центру по горизонтали и по вертикали, единица измерения не «прыгает» и не переносится.

## Что изменится

**1. HTML/печатная версия КП** (`src/lib/documents/quote-html.ts`)
- Отдельный класс ячейки `qty` вместо общего `num`: `text-align:center`, `vertical-align:middle`, `width:96px`, `white-space:nowrap`, табличные цифры.
- Заголовок «Кол-во» тоже по центру, той же ширины.
- Единица измерения выводится под числом мелким текстом, чтобы длинные «шт./час» не растягивали колонку.

**2. PDF КП** (`src/lib/documents/pdf.server.ts`)
- Для колонки `qty` в КП, счёте, договоре, акте: `align: "center"` вместо `right`, единая доля ширины.
- Вертикальное центрирование значения относительно высоты строки (сейчас текст прижат к первой строке, когда название позиции занимает несколько строк).

**3. Документы заказа** (`src/lib/documents/build.server.ts`)
- Тот же стиль колонки количества в HTML-шаблонах счёта/договора/акта/КП по заказу.

**4. Редактор КП в админке** (`src/components/admin/quotes/QuoteItemsPanel.tsx`)
- Поле «Кол-во» фиксированной ширины, текст внутри инпута по центру, одинаковая высота с соседними полями (`h-8`, `items-center`), скрытие спиннеров для ровного вида.

КП Промо (`promo-quote-html.ts`, `PromoItemsTable.tsx`, `promo-xlsx.browser.ts`) не трогаем.

## Проверка
- Прогон существующих регрессионных тестов PDF/HTML.
- Визуальная проверка PDF и HTML КП с длинными названиями позиций и разделами.

## Технические детали
- Вертикальное центрирование в PDF реализуется расчётом смещения: `y = rowTop - (rowHeight - lineHeight)/2` для одностроковых ячеек, как уже делается для номера строки.
- В HTML достаточно `td.qty { text-align:center; vertical-align:middle; width:96px; }` и обновления `th`.
