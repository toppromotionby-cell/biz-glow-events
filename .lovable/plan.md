## Что уже есть в коде

В `src/lib/leads.functions.ts` и `src/lib/orders.functions.ts` уже реализована функция `notifyTelegram()`, которая шлёт HTML-сообщение через connector gateway Lovable. Каждое уведомление содержит:

**Лид (форма «Связаться»):** имя, телефон, email, компанию, дату мероприятия, сообщение, UTM-метки.

**Заказ из корзины:** ID заказа, клиента (имя/телефон/email/компания), сумму, дату, источник, комментарий, состав корзины (позиции с qty × ценой).

Каждая отправка логируется в таблицу `telegram_logs`. Если Telegram недоступен — срабатывает email-фолбэк на `hello@event-hub.by`.

## Что нужно сделать

### 1. Создать Telegram-бота (делает пользователь)
1. Открыть @BotFather в Telegram → `/newbot` → задать имя и username.
2. Сохранить токен бота (выглядит как `1234567890:ABC...`).
3. Создать группу/канал для уведомлений (например, «event-hub.by — заявки») и добавить туда бота как администратора. Либо использовать личный чат с ботом — тогда нужно один раз ему написать.

### 2. Подключить Telegram-коннектор
Использую `standard_connectors--connect` с `connector_id: "telegram"`. В диалоге пользователь вставит токен бота. После этого в проекте автоматически появится переменная `TELEGRAM_API_KEY` (это ключ шлюза Lovable, не сам токен бота).

### 3. Получить и сохранить `TELEGRAM_CHAT_ID`
- Если уведомления должны идти в группу: добавить бота в группу и попросить пользователя прислать любое сообщение в неё; затем дёрнуть `getUpdates` через шлюз и достать `chat.id` (для групп — отрицательное число вида `-1001234...`).
- Если в личку: пользователь пишет `/start` боту, дёргаем `getUpdates`, берём `chat.id`.

После того как ID найден — добавляю его как секрет `TELEGRAM_CHAT_ID` через `add_secret`.

### 4. Проверить, что всё работает
- Прочитать секреты `fetch_secrets` — должны быть `LOVABLE_API_KEY`, `TELEGRAM_API_KEY`, `TELEGRAM_CHAT_ID`.
- Сделать тестовую отправку через `code--exec` (curl на `connector-gateway.lovable.dev/telegram/sendMessage`) — убедиться, что сообщение пришло в нужный чат.
- В таблице `telegram_logs` сразу появятся записи `status='sent'` для следующих заявок.

### 5. (Опционально) Фолбэк-вопрос
Если пользователь хочет получать уведомления и в личку, и в группу — можно либо завести две `chat_id` через запятую и шлать в обе, либо использовать одну группу с несколькими администраторами. По умолчанию делаю **одну точку** (`TELEGRAM_CHAT_ID`).

## Уточняющие вопросы перед запуском

1. **Куда слать уведомления** — в группу с менеджерами или в личный чат одного человека?
2. **Готовы ли вы прямо сейчас создать бота через @BotFather?** Если да — после переключения в build mode я попрошу вставить токен и затем `chat_id`.

## Технические детали

- Точка отправки: `https://connector-gateway.lovable.dev/telegram/sendMessage` с заголовками `Authorization: Bearer $LOVABLE_API_KEY` и `X-Connection-Api-Key: $TELEGRAM_API_KEY`.
- Формат сообщения: HTML (`parse_mode: "HTML"`), html-escape уже сделан функцией `tgEsc()`.
- Никаких миграций БД не требуется — таблица `telegram_logs` уже существует.
- Никаких новых файлов кода писать не нужно — вся логика уже внедрена в `submitLead` / `submitOrder`. Работа сводится к настройке секретов.
- Вебхуки/входящие сообщения **не настраиваем** — задача только в исходящих уведомлениях.
