# Эталонная смета, шаблоны КП и единая база знаний

Загруженный файл «КП Топ промоушн — Белкоммунмаш от 24.07.26» берётся как эталон. Работа разбита на 5 этапов; после каждого система остаётся рабочей, старые КП не ломаются.

## 1. Анализ текущей системы

Что уже есть:
- Админка: `/admin/documents` с разделами «КП» (`quotes`, `quote_items`), «КП промо» (`promo_quotes`, `promo_quote_items`), «Финансовые документы», «Презентации», «База знаний».
- Расчёты вынесены в единые модули `quotes-model.ts` / `promo-quote-model.ts`, они же питают live-превью, PDF (`pdf.server.ts`) и XLSX.
- Есть НДС, комиссия, менеджмент, скидка, валюта, версии (`quote_versions`, `promo_quote_versions`), статусы, публичная ссылка `/kp/<token>`, проверки документа, печатные пресеты, мультикомпании.
- Уже есть флаги `is_template` / `template_name` у обоих типов КП — но полноценного механизма «создать по образцу» и библиотеки шаблонов нет.
- База знаний ограничена документами: `doc_contacts`, `doc_item_catalog`, `doc_text_snippets`; наполняется только при сохранении КП/промо/заказов, используется только в подсказках конструкторов.

Чего не хватает по сравнению с эталонной сметой:
1. **Флаг «включать в итог» (колонка K: 1/0)** — опциональные позиции («предложено как дополнение, в итог не входит») сейчас нельзя показать в смете, не включая в сумму.
2. **Группы-связки** (`=SUM(J62:J64)*K62`) — несколько строк считаются одним блоком и включаются/исключаются вместе.
3. **Двумерное количество** (чел × час: колонки D/E и F/G) — сейчас есть `qty` и безымянный `multiplier`, без подписи второй единицы.
4. **Информационные строки с нулевой ценой** (гастрольное удостоверение, футболки) — как «0 / по запросу».
5. **Секции-альтернативы** («Фотозона — дополнительный вариант») и подытоги по включённому/опциональному.

## 2. Этапы

### Этап 1 — эталонная модель позиции (КП и Промо)
- Поля позиции: `included` (в итог / опция), `group_key` (связка строк), `qty_unit` + `qty` и `rate_unit` + `rate_qty` (двумерный расчёт `Всего = qty × rate_qty`), `is_info` (строка без цены).
- Итоги: базовая сумма только по `included`; отдельно «Опции (не в итоге)» с их суммой; подытоги по секциям; НДС/комиссия/менеджмент считаются от включённой базы — существующая логика сохраняется.
- В превью, PDF и XLSX: опции визуально отделены (приглушённая строка + пометка «опция»), в XLSX сохраняются живые формулы, включая колонку 1/0 и `SUM(...)` для групп.
- Миграция добавляет колонки с безопасными значениями по умолчанию (`included = true`), поэтому все существующие КП считаются как раньше.

### Этап 2 — шаблоны смет и «Создать по образцу»
- Таблицы `estimate_templates` (имя, тип: quote/promo, описание, настройки документа, версия, активность) и `estimate_template_items` (секция, позиция, единицы, кол-во, цена, примечание, включение, группа, порядок).
- Импорт эталонной сметы в шаблон «День открытых дверей / промо-мероприятие под ключ» (разделы: техоборудование, сценическая программа, анимация, аттракционы, мастер-класс, фотозона, съёмка, аквагрим, доп. активности, организация).
- В списке КП и промо — кнопка «Создать по образцу» с выбором шаблона, предпросмотром структуры и пунктом «пустой документ».
- Управление шаблонами: `/admin/documents/templates` — список, создание шаблона из готового КП («Сохранить как шаблон»), редактирование, версия шаблона, деактивация. Обновление шаблона не трогает уже созданные документы.
- Режимы: «строгий» (обязательные секции шаблона нельзя удалить, проверка структуры во вкладке «Проверки») и «гибкий» (по умолчанию).

### Этап 3 — единая база знаний
- Новое хранилище `kb_entries` (тип записи, заголовок, текст, данные JSON, цена, единица, теги, категория, источник, `source_table` + `source_id`, ключ дедупликации, счётчик использования, дата обновления, статус модерации) + `kb_sync_logs` (источник, действие, результат, ошибка, время).
- Типы записей: услуга/товар, позиция сметы, текстовый блок, условие, FAQ, контрагент, кейс, слайд презентации, промо-акция.
- Наполнение (server-side, ошибки не ломают сохранение): при сохранении КП и промо, при создании/смене статуса заказа, при сохранении презентации, при сохранении карточки каталога (зоны, услуги, техника, продакшн, аттракционы), при изменении цен и описаний.
- Существующие `doc_contacts` / `doc_item_catalog` / `doc_text_snippets` не удаляются: они переносятся в `kb_entries` фоновой синхронизацией и остаются источником подсказок до полного перехода.
- Дедупликация по нормализованному ключу, объединение дублей, счётчик и дата последнего использования.

### Этап 4 — база знаний по всему проекту
- Админка `/admin/documents/knowledge` расширяется: вкладки по типам записей, поиск, фильтры по источнику и тегам, дубли, модерация, ручная синхронизация, журнал синхронизации, массовые действия (существующие функции удаления и очистки сохраняются).
- Автоподстановка: в конструкторах КП/промо (позиции, цены, примечания, состав), в презентациях (тексты слайдов), в карточках каталога (описания и характеристики — как предложение, не автозамена).
- Публичная часть: поиск по сайту и FAQ читают опубликованные записи БЗ через публичную серверную функцию; на страницах услуг — блок «Часто спрашивают» и связанные позиции.
- Модерация: на публичные страницы попадают только записи со статусом «одобрено».

### Этап 5 — промо, каталог и связи
- Позиции в КП/промо добавляются прямо из каталога (поиск по каталогу + БЗ в одном списке) с сохранением ссылки на источник.
- Связка КП ↔ заказ ↔ клиент ↔ промо-акция; из КП можно собрать презентацию по позициям.
- Аналитика документов дополняется топом позиций и разделов, «что чаще всего включают/исключают» — данные идут в рекомендации калькулятора и блока «Готовый пакет».

## 3. Новые сущности

Таблицы: `estimate_templates`, `estimate_template_items`, `kb_entries`, `kb_sync_logs`.
Колонки: `quote_items` и `promo_quote_items` — `included`, `group_key`, `qty_unit`, `rate_unit`, `rate_qty`, `is_info`, `source_kind`, `source_id`.
Доступ: чтение/запись — admin и manager через существующую матрицу прав (`documents.*`, новое право `knowledge.moderate`); публичное чтение БЗ — только одобренные записи, через серверную функцию.

## 4. Изменения в UI

- Таблица позиций КП/промо: колонка-переключатель «в итог», пометка «опция», объединение строк в группу, вторая единица измерения, строки-справки без цены.
- Панель итогов: «Стоимость позиций», «Опции (не в итоге)», подытоги секций.
- Список КП/промо: кнопка «Создать по образцу», действие «Сохранить как шаблон».
- Новый раздел «Шаблоны смет» и расширенная «База знаний» с журналом синхронизации.
- Публично: блок FAQ/«часто спрашивают» на карточках услуг, БЗ в поиске.

## 5. Риски и что проверить

- Расчёты: любое изменение модели проверяется юнит-тестами на эталонной смете (сумма включённых позиций, опции, группы, НДС, комиссия).
- Совместимость: миграции только добавляют колонки со значениями по умолчанию; старые документы должны считать ту же сумму — сверяем до/после.
- Производительность БЗ: наполнение выполняется после сохранения и не блокирует ответ; ошибки пишутся в журнал.
- Публичная выдача БЗ: показываем только одобренные записи без цен-себестоимости и внутренних примечаний.

Начинаю с этапа 1 и импорта эталонной сметы в шаблон, если план подходит.
