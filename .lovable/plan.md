# Ember Copilot — ИИ-управленец в админке

Док-панель с ИИ-помощником на всех страницах админки. Голос на входе и на выходе, полный доступ ко всем модулям (контент, заявки, документы, почта и рассылки), любое изменение — сначала превью, потом ваше утверждение. Доступ только у главного админа.

## Как это выглядит

Кнопка-иконка «Ember» (фирменный огонёк в стилистике сайта) закреплена в правом нижнем углу любой страницы админки. Клик или Cmd/Ctrl+K открывает панель справа шириной ~460 px (можно растянуть, можно свернуть в «пилюлю»).

```text
┌──────────────────────────────┐
│ ✦ Ember · Помощник      _ ✕ │
├──────────────────────────────┤
│ Контекст: Заявки → 31/08-04  │
├──────────────────────────────┤
│  диалог (текст, голос, файлы)│
│  ┌ Карточка плана ─────────┐ │
│  │ Что сделаю: 4 шага      │ │
│  │ ▸ Превью изменений      │ │
│  │ [Утвердить][Правки][✕]  │ │
│  └─────────────────────────┘ │
├──────────────────────────────┤
│ 🎙  [ поле ввода ]      ➤    │
└──────────────────────────────┘
```

Панель знает, на какой вы странице и какая запись открыта, — «сделай скидку 10%» работает без указания номера заявки.

## Логика работы

1. Вы говорите или пишете задачу (можно приложить скрин, PDF, таблицу).
2. Помощник читает данные, при необходимости ищет в интернете и в базе знаний.
3. Отвечает **планом**: что понял, что сделает по шагам, чего не хватает.
4. Показывает **превью**: таблица «было → стало» по каждой записи, для текстов — подсветка правок, для документов — PDF-превью.
5. Вы жмёте «Утвердить» (или «Правки» — уточняете голосом/текстом, план пересобирается).
6. Изменения применяются одной транзакцией, в чат приходит отчёт со ссылками на изменённые записи и кнопкой «Откатить».
7. Итог автоматически уходит в Информационную базу, откуда его видят все, у кого есть права, и оба Telegram-бота.

Ничего не применяется без утверждения. Даже безопасные действия проходят превью — как вы просили.

## Что он умеет

**Контент сайта**: каталог (зоны, услуги, техника, продакшн, аттракционы), разделы и категории, блог, кейсы, отзывы, тексты и SEO-описания, промокоды. Массовые операции: «подними цены на свет на 7%», «перепиши описания всех фотозон под свадьбы», «скрой всё, чего нет в наличии».

**Заявки и документы**: статусы, позиции, внутренние заметки, сборка КП/смет/договоров/актов, презентации, экономика и маржа. «Собери КП по заявке 31/08-04 из прошлогоднего шаблона и покажи маржу».

**Почта и рассылки**: шаблоны писем, кампании, отправители, черновики ответов, разбор входящих. Реальная отправка — всегда отдельное подтверждение с показом списка получателей.

**Файлы**: находит любой файл в хранилищах, показывает, отдаёт ссылкой, отправляет в Telegram, принимает загрузку прямо в панель (фото → в карточку каталога, XLSX → импорт позиций).

**Аналитика и гигиена**: сводки по заявкам и деньгам, поиск дублей, пустых полей, битых ссылок и товаров без фото — с готовым планом починки.

**Знания и обучение**: «запомни: минимальный чек 900 BYN» — факт уходит в общую базу, и его сразу знают оба бота. «Забудь про…» удаляет.

**Внешний интеллект**: свободный веб-поиск и обращение к нескольким бесплатным моделям для сравнения вариантов (тексты, идеи, проверка фактов) — с указанием источников в плане.

## Голос

Кнопка микрофона: запись → распознавание речи на сервере (русский) → текст попадает в поле ввода, можно поправить перед отправкой. Ответы помощника озвучиваются (кнопка «динамик» включает/выключает озвучку, скорость и голос — в настройках). Работает режим «без рук»: сказали → услышали план → сказали «утверждаю».

## Роли и безопасность

- Панель видит и открывает **только главный админ** (роль `admin` + отдельный флаг «оператор Ember»). Для остальных кнопки нет, серверные функции возвращают отказ.
- Каждое действие в реестре имеет свой уровень риска: чтение / черновик / изменение / необратимое (удаление, публикация, отправка писем). Необратимые требуют повторного подтверждения фразой в карточке.
- Всё пишется в журнал: кто, когда, что попросил, что применилось, откат.
- Лимиты: максимум записей в одной операции, запрет на массовое удаление, ограничение по количеству писем за раз.

## Что появится в админке

- Плавающая кнопка и панель на всех страницах `/admin/*`.
- Страница **«Ember»** (`/admin/copilot`): история диалогов, все планы (ожидают / утверждены / отклонены), журнал применённых изменений с откатом, настройки (голос, озвучка, лимиты, какие модули разрешены, доступ операторов).
- В «Информационной базе» — новый источник «Ember», чтобы видеть, чему помощник научился.

## Техническая часть

**База данных** (новые таблицы, RLS только для admin, GRANT по правилам проекта):
- `copilot_sessions` — диалоги с контекстом страницы.
- `copilot_messages` — реплики, вложения, ссылки на планы.
- `copilot_runs` — предложенный план: шаги, diff-превью (jsonb), статус (draft / pending / approved / applied / rejected / rolled_back), результат, снапшот «до» для отката.
- `copilot_audit` — журнал применённых операций.
- `copilot_settings` — голос, лимиты, разрешённые модули, список операторов.
- `assistant_memory` переиспользуем как есть (уже общий для ботов), добавляем источник `copilot`.

**Серверный слой** `src/lib/copilot/`:
- `registry.ts` — декларативный реестр инструментов: имя, модуль, уровень риска, zod-схема аргументов, функции `preview()` и `apply()`. Один источник правды и для модели, и для UI, и для тестов.
- `tools/*.server.ts` — реализации по модулям: `catalog`, `content`, `orders`, `documents`, `mail`, `files`, `analytics`, `hygiene`, `knowledge`.
- `plan.server.ts` — сборка плана, расчёт diff-превью, применение с транзакцией и снапшотом, откат.
- `agent.server.ts` — цикл модели (AI SDK, `streamText`, tool calling, `stepCountIs(50)`) с обязательным `needsApproval` на всё, что пишет.
- `voice.server.ts` — распознавание речи и синтез через Lovable AI Gateway.
- `guard.server.ts` — проверка роли, лимитов и уровня риска перед каждым инструментом.

**Транспорт**: стриминг через server route `src/routes/api/copilot/chat.ts` (`useChat` на клиенте), применение и откат — через `createServerFn` с `requireSupabaseAuth`.

**Модель**: `google/gemini-3.7-flash` для диалога и инструментов, `google/gemini-3.1-pro-preview` для сложного планирования и разбора документов; веб-поиск — существующий `research.server.ts`.

**Клиент** `src/components/copilot/`: `CopilotDock`, `CopilotLauncher` (иконка), `CopilotChat`, `PlanCard`, `DiffPreview` (таблица «было → стало»), `VoiceButton`, `ContextChip`. Контекст страницы даёт хук `useCopilotContext` из маршрута и открытой записи. Иконка — фирменный «ember»-огонёк на графитовом фоне, токены существующей темы, без хардкода цветов.

**Общий мозг**: реестр инструментов и память подключаются к `src/lib/botkit/`, поэтому Telegram-боты получают те же знания и тот же формат карточек-планов.

**Автопроверки**: тесты на реестр (у каждого инструмента есть схема, превью и уровень риска), на запрет применения без утверждения, на отказ для не-админа, на корректность diff и отката, на лимиты массовых операций, на парсинг голосовых команд.

## Этапы

1. Схема БД, реестр инструментов, гвардия ролей, тесты каркаса.
2. Панель, лаунчер, чат со стримингом, контекст страницы.
3. Планы и превью-diff, применение, откат, журнал.
4. Инструменты: контент и каталог.
5. Инструменты: заявки, документы, презентации, экономика.
6. Инструменты: почта, рассылки, файлы, аналитика и гигиена.
7. Голос: распознавание и озвучка, режим «без рук».
8. Страница `/admin/copilot`, настройки, связка с базой знаний и ботами, финальные автопроверки.
