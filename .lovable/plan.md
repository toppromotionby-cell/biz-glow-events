# Презентации: упрощение, починка и связки с остальным сайтом

## Что подтверждено в коде сейчас

- Модуль большой: редактор `admin/documents/presentations/$id` (896 строк) + 14 компонентов + 12 файлов логики (`model`, `design`, `content-spec`, `slide-spec`, `zones`, `snap`, `fit`, `logo-plan`, `text-metrics`, `audit`, `check`, `pdf.server`).
- Слайд рисуется дважды разными движками: на экране — React `SlideCanvas`, в PDF — `pdf.server.ts` (jsPDF). Общая только модель, раскладка считается в двух местах — отсюда расхождения «превью ≠ PDF».
- **Найденная ошибка:** в интерфейсе выбирается 7 шаблонов (`TEMPLATE_LABELS`: светлый, тёмный, акцентный, ночная волна, закат, изумруд, сияние), а серверные функции `createPresentation` и `savePresentation` принимают только `light | dark | accent`. Выбор любого из четырёх новых шаблонов ломает сохранение — правки не записываются.
- Нет публичной ссылки на презентацию: у КП есть `/kp/$token`, у презентаций — только PDF и просмотр внутри админки.
- Нет истории версий/снимков (в отличие от документов).
- Список презентаций не связан с заказом: фильтр есть по компании и КП, привязки к заказу нет.

## Что сделаем

### 1. Починка (обязательно, первым)
- Единый источник списка шаблонов: серверные валидаторы берут значения из `PRESENTATION_TEMPLATES`, а не из захардкоженного enum. Плюс тест, который сверяет схему сохранения со списком шаблонов модели.
- Проверка колонки `template` в базе: если стоит ограничение на 3 значения — миграция, расширяющая его до 7.
- Ошибка сохранения перестаёт быть «тихой»: понятное сообщение и статус «не сохранено» вместо молчаливого отката.

### 2. Упрощение (меньше кода, то же поведение)
- Один расчёт раскладки слайда: выносим геометрию (зоны фото/текста/цены/логотипа) в чистую функцию `computeSlideLayout`, которую используют и экранный холст, и PDF. `design.ts`/`slide-spec.ts`/`zones.ts`/`fit.ts` сводим к одному слою без дублирующих формул.
- Редактор разбиваем на части: страница-контейнер + `usePresentationEditor` (состояние, автосохранение, горячие клавиши) + панели. Файл маршрута сокращается примерно втрое, поведение не меняется.
- Панели «Аудит» и «Сверка с КП» объединяем в одну вкладку «Проверка» — как в документах (`DocStatusBar`), чтобы у пользователя был один список замечаний, а не два.
- Настройки слайда упрощаем: сверху «Быстро» (тип, текст, фото, цена), ниже сворачиваемая «Тонкая настройка» (зоны, масштабы, ручные позиции). Сейчас всё вываливается одним длинным списком.

### 3. Что важно добавить
- **Публичная ссылка на презентацию** по токену (как у КП): просмотр в браузере без входа, кнопка «Скопировать ссылку», отключение доступа. Логика доступа общая с КП.
- **Отправка клиенту письмом** через существующий транзакционный почтовый слой, с записью в историю.
- **Версии/снимки** при ручном сохранении и перед «Пересобрать из КП» + откат — по образцу истории документов.
- **Связь с заказом**: презентация видна в карточке заказа и в списке фильтруется по заказу; из заказа можно создать презентацию по его КП.
- **Синхронизация с КП**: показывать, что позиции КП изменились после сборки слайдов, и предлагать точечное обновление затронутых слайдов вместо полной пересборки.

### 4. Сквозная проверка «ничего не сломалось»
- Тесты на раскладку: одна и та же модель даёт одинаковые координаты в экранном холсте и в PDF (снимки геометрии).
- Тесты валидаторов: любой шаблон/тип слайда из модели проходит `create`/`save`.
- Прогон существующих unit-тестов (231) и e2e-набора: список презентаций, редактор, PDF, публичная ссылка, страница заказа, документы/КП — проверяем, что общие компоненты (`FullscreenLayer`, `EditorWorkspace`, `DocStatusBar`, просмотрщик PDF) не задеты.
- Права: публичная ссылка отдаёт только презентацию по токену, без цен из закрытых источников и без доступа к админ-данным.

## Порядок работ

1. Починка шаблонов + тесты валидаторов.
2. Единый расчёт раскладки, сверка превью и PDF.
3. Разбор редактора на хук и панели, объединение «Проверка».
4. Публичная ссылка + отправка письмом.
5. Версии и откат.
6. Связь с заказом и умная синхронизация с КП.
7. Полный прогон тестов и живая проверка в браузере.

## Технические детали

- `src/lib/presentations.functions.ts`: `z.enum([...PRESENTATION_TEMPLATES])`, единая схема слайда.
- Новый `src/lib/presentations/layout.ts` — чистая геометрия; `SlideCanvas.tsx` и `pdf.server.ts` только рисуют по её результату.
- Публичная страница — маршрут по токену рядом с `kp.$token`, чтение через server fn с `supabaseAdmin` и проверкой токена; колонка `share_token` + миграция с GRANT/RLS.
- Версии — таблица снимков `presentation_versions` (jsonb слайдов) с RLS для staff.
