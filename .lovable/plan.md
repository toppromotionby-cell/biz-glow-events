# Калькулятор на реальных позициях + рекомендации по спросу

## Цель
1. Калькулятор считает предварительную смету только по реальным позициям и ценам каталога сайта (никаких зашитых цифр).
2. Со временем и калькулятор, и блок «Наши рекомендации» показывают в первую очередь те позиции, по которым чаще всего идут запросы и заказы.

## Что сейчас
- `/calculator` и блок-калькулятор на главной считают по жёстко зашитому списку из 7–8 «модулей» с выдуманными ценами и коэффициентами. С каталогом это никак не связано.
- «Наши рекомендации» уже сортируются по популярности, но сигнал берётся только из заказов и корзин **зарегистрированных** пользователей. После перехода на гостевой заказ у большинства заказов пользователь пустой, то есть основной спрос в рейтинг не попадает.
- Единственного места, где копится спрос (просмотры, запросы КП, добавления в корзину), сейчас нет — данные только в заказах и черновиках корзин.

## Что делаем

### 1. Единый счётчик спроса
Новая таблица спроса: тип позиции, id позиции, тип события (просмотр карточки, «Подробнее», запрос КП, в корзину, заказ), дата. Записи пишутся с сервера по факту действия, анонимно (без персональных данных).

Итоговый рейтинг позиции = взвешенная сумма событий за последние ~180 дней с затуханием по времени:
заказ (вес 8) > запрос КП (5) > добавление в корзину (3) > «Подробнее» (1) > просмотр карточки (0.5).
Заказы учитываются и у гостей, и у зарегистрированных.

### 2. Калькулятор на данных каталога
Страница `/calculator` и блок на главной перестраиваются:
- Позиции подгружаются с сервера из опубликованного каталога (зоны, оборудование, услуги, продакшн, аттракционы) с их реальными ценами.
- Наверху — блок «Чаще всего заказывают»: 8–12 позиций с максимальным рейтингом спроса, выбираются в один клик.
- Ниже — выбор остальных позиций по разделам с поиском.
- Количество/часы/дни по каждой позиции ограничиваются теми же правилами, что и в корзине (единицы измерения из прайса).
- Итог: сумма реальных цен позиций (используются существующие правила прайса, включая почасовые тарифы). Позиции без цены показываются как «по запросу» и выводятся отдельной строкой, не ломая сумму.
- Убираются выдуманные коэффициенты гостей/дней/площади и «логистика». Остаются только те параметры, которые реально влияют на цену позиции (часы/дни/кол-во).
- Кнопки: «Отправить на точный расчёт» (заявка со всем составом) и «Перенести в корзину».

### 3. «Наши рекомендации»
- Рейтинг берётся из нового счётчика спроса (заказы гостей теперь считаются).
- Fallback без данных: как сейчас — свежие опубликованные позиции.
- Позиции без спроса не вытесняют популярные; выдача обновляется автоматически по мере накопления запросов.

## Технические детали
- Миграция: таблица `demand_events` (entity_type, entity_id, event, weight, created_at) + GRANT + RLS (вставка только через серверные функции с service role, чтения из клиента нет), индекс по (entity_type, entity_id, created_at).
- Запись событий: серверная функция `trackDemand` в `src/lib/demand.functions.ts`, вызывается из карточки каталога, модалки «Подробнее», добавления в корзину, `QuickQuoteRequest` и оформления заказа (`orders.functions.ts`).
- Скоринг: `src/lib/demand.server.ts` — агрегирующий запрос с затуханием, кэш в памяти на 5 минут; используется в `home.functions.ts` (вместо текущего `buildPopularityScores`) и в новой `getCalculatorCatalog`.
- Калькулятор: новая серверная функция `getCalculatorCatalog` (id, slug, title, type, unit, price, popularity), route loader + `ensureQueryData`; расчёт по строкам прайса через существующие `src/lib/pricing.ts` и `priceFrom`.
- `src/routes/calculator.tsx` и `src/components/GuestEstimator.tsx` переписываются на эти данные; статические массивы `BLOCKS`/`MODULES` удаляются.
