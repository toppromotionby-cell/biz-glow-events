# Единый источник данных для каталога, меню и направлений

## Проблема

Сейчас разделы и направления живут в трёх разных местах:

- меню «Каталог» в шапке и футер — жёсткий список из 5 пунктов в коде (`SiteChrome.tsx`);
- страница `/catalog` — отдельный жёсткий список из 4 карточек (нет «Аттракционов»);
- направления (категории) — таблица `catalog_categories`, но они видны только фильтрами внутри раздела и нигде не показываются как навигация.

Поэтому при добавлении нового раздела или направления в админке они не появляются ни в меню, ни на странице каталога.

## Что сделаем

Один источник — база. Всё, что появляется в админке, автоматически появляется в меню, на `/catalog` и внутри разделов.

### 1. Данные и админка

- Расширяем справочник направлений: добавляем поля «URL-имя» (для ссылок), «Описание», «Показывать в меню», «Иконка/картинка» (опционально) и порядок сортировки.
- Новый справочник разделов каталога (зоны, оборудование, услуги, производство, аттракционы): название, описание, иконка, порядок, «Показывать в меню/каталоге». Маршруты остаются прежними — редактируется только подача.
- Новая страница админки «Каталог → Разделы и направления»: список разделов, внутри каждого — направления с drag-порядком, переименованием, скрытием и удалением. Существующий выпадающий выбор категории в редакторе товара продолжает работать с тем же справочником.

### 2. Публичная часть — единый компонент

- Один серверный запрос `getCatalogNavigation()` отдаёт разделы + направления + количество опубликованных позиций в каждом.
- Меню «Каталог» в шапке становится мега-меню: колонка на раздел, внутри — направления со счётчиками.
- Страница `/catalog` строится из тех же данных: карточка на каждый раздел (включая «Аттракционы») + чипы направлений внутри карточки.
- Футер и мобильное меню берут тот же список.
- Клик по направлению ведёт на раздел с фильтром (`/zones?category=...`) — фильтр по URL уже поддерживается сеткой каталога.
- Пустые направления (0 опубликованных позиций) в навигации не показываются, чтобы не было тупиков.

### 3. Единый стиль

Один набор компонентов для всех трёх поверхностей: карточка раздела, чип направления, счётчик. Иконки, градиенты и типографика — из текущих токенов, чтобы мега-меню, `/catalog` и футер выглядели как одна система.

## Технические детали

- Миграция: `catalog_categories` + колонки `slug`, `description`, `visible`, `icon`; новая таблица `catalog_sections` (ключ = существующий `entity_type`) с GRANT'ами и RLS (чтение публично, запись — только staff).
- Серверная функция `getCatalogNavigation` в `src/lib/catalog.functions.ts` через `supabaseAdmin` (как остальные публичные чтения), с counts по опубликованным позициям; кэш в TanStack Query.
- `SiteChrome.tsx`: `CATALOG_NAV` заменяется данными из запроса, статический массив остаётся только как fallback при ошибке/SSR.
- `src/routes/catalog.tsx`: статический `CATALOGS` заменяется на данные навигации + JSON-LD `ItemList` по разделам.
- Новые компоненты: `src/components/catalog/CatalogNav*.tsx` (мега-меню, карточка раздела, чипы).
- Админка: `src/routes/admin.catalog.sections.tsx` + пункт в `AdminSidebar`.

## Порядок работ

1. Миграция базы и админ-страница справочников.
2. Серверная функция навигации + кэш.
3. Мега-меню, `/catalog`, футер на единых компонентах.
4. Проверка ссылок с фильтрами и SEO-разметки.
