# Единый канвас для «Документов» и «Презентаций» (модель Canva)

## Что сейчас (инвентаризация)

Два параллельных мира с почти одинаковыми задачами и полностью разным кодом.

Презентации (~2 700 строк логики + ~1 900 UI):
- `model.ts` (484) — слайд как набор полей: заголовок, подзаголовок, фото, спеки, цена, плюс `SlideLayoutOverrides` с зонами (`photoZone`, `textZone`, `priceZone`, `LogoZone`) и масштабами.
- `design.ts` (546), `content-spec.ts` (412), `slide-spec.ts` (328), `fit.ts`, `logo-plan.ts` (289), `zones.ts`, `snap.ts`, `audit.ts`, `text-metrics.ts` — авторасчёт раскладки: зона → прямоугольник → кегль → проверка переполнения.
- `SlideLayoutOverlay.tsx` (582) — своя математика drag/resize (8 маркеров, Shift/Alt, снапы, замер DOM-рамок), `SlideCanvas.tsx` (512), `SlideSettingsPanel.tsx` (409), `BlockToolbar.tsx` (238).
- `pdf.server.ts` (428) — отдельный рисовальщик по тому же спеку.

Документы (КП стандартное и промо, ~4 800 строк):
- `doc-layout.ts` (364), `quote-html.ts` (664), `promo-quote-html.ts` (338), `logo-layout.ts` (223), `density.ts`, `sheet.ts`, `brand.ts`.
- Два роут-редактора: `admin.documents.quotes.$id.index.tsx` (904) и `admin.documents.promo.$id.index.tsx` (722) — почти одинаковые панели, разные реализации.
- Два PDF-рендера: `pdf.server.ts` (2 182) и `promo-pdf.server.ts` (590).

## Диагноз (главное)

1. Дублирование ядра. Автосохранение, история, шапка/логотипы, зум-сцена, статус-бар, превью и PDF реализованы отдельно для презентаций, для КП и для промо-КП. Любая правка делается трижды.
2. Раскладка не объектная. У слайда нет элементов — есть «зоны» и десятки override-полей. Из-за этого нельзя добавить произвольный текст, фигуру или вторую картинку, а drag сводится к «попасть в зону».
3. Своя математика трансформаций. `SlideLayoutOverlay` вручную считает дельты, снапы, пропорции и замеряет DOM — источник рассинхронов рамок и багов при зуме.
4. Три источника геометрии. Превью, PDF и оверлей собираются разными путями, поэтому расхождения возвращаются после каждой правки.
5. UX: базовые действия дороже 3 кликов (создать слайд из шаблона, поменять раскладку, вставить логотип), контекстный тулбар частично дублирует правую панель.
6. Перерендеры: правка одного поля перестраивает весь документ и весь список слайдов.

## Что делаем

Один редактор для всего. Документ и презентация — это `Page[]`, страница — массив объектов. Разница только в формате листа: A4 210×297 мм против 1280×720.

1. Модель элементов
   - `Element = { id, type, x, y, w, h, rotation, zIndex, locked, props }`.
   - Типы: `text`, `image`, `shape`, `logo`, `table`, `spacerRepeat` (повторяемый блок позиций КП).
   - Бизнес-данные КП (позиции, количества, суммы, НДС, промокоды) остаются в модели документа; элемент `table` хранит только геометрию, стиль и ссылку на источник данных. Формулы и расчёты не трогаем.
   - Шаблоны — просто JSON-массив элементов; «создать из шаблона» = вставка JSON.

2. Единый канвас
   - `CanvasStage` (зум/скролл/фит) + `CanvasPage` (лист) + `CanvasElement` (рендер по `type`).
   - Трансформации через `react-moveable`: drag, resize, rotate, snap-линии, keep-ratio, group-select. Своя математика удаляется.
   - Тот же `CanvasPage` в миниатюрах, полноэкранном показе и печатном роуте — без второго рендерера.

3. Контекстный тулбар
   - Верхняя панель зависит от выделения: текст — шрифт/кегль/цвет/выравнивание; картинка — обрезка/скругление/фильтр; таблица — колонки/итоги; ничего не выделено — формат страницы, фон, тема.
   - Правые «мега-панели» (`SlideSettingsPanel`, панели КП) ужимаются до вкладок «Страницы», «Данные», «Проверка», «История».

4. История и автосохранение
   - Общий `editor-history.ts` (уже есть) для обоих разделов: снапшот на завершение жеста, лимит 60, Ctrl/Cmd+Z / Shift+Z.
   - Автосохранение 3 с + индикатор в статус-баре; кнопки «Сохранить» нет нигде.

5. Один рендер — один PDF
   - PDF рисуется обходом того же `Element[]` (`renderElements`), поэтому превью и файл совпадают по определению. Старые ветки ручной разметки удаляются.

6. Совместимость
   - Миграция «на лету»: старые слайды и КП конвертируются в `Element[]` детерминированной функцией из текущего авторасчёта (`content-spec` / `doc-layout`) при первом открытии; в БД пишется уже новая структура. Ничего не переверстывается вручную.

## Порядок работ

1. Ядро: типы элементов, `CanvasStage/CanvasPage/CanvasElement`, `react-moveable`, история, автосохранение.
2. Презентации на новое ядро + миграция слайдов + PDF из элементов.
3. Документы (стандартное и промо КП) на то же ядро, один редактор вместо двух, один PDF-путь.
4. Удаление старого: `zones.ts`, `logo-plan.ts`, `SlideLayoutOverlay`, дублирующие панели и ветки в `pdf.server.ts` / `promo-pdf.server.ts`.
5. Тесты и визуальная проверка: юнит на миграцию и геометрию, сравнение превью и PDF постранично.

## Технические детали

- Новые модули: `src/lib/canvas/model.ts` (типы, нормализация, миграции), `src/lib/canvas/render.ts` (общий обход элементов), `src/lib/canvas/pdf.server.ts`, `src/components/admin/canvas/*` (`CanvasStage`, `CanvasPage`, `CanvasElement`, `SelectionLayer` на `react-moveable`, `ContextToolbar`, `PagesRail`).
- Зависимость: `react-moveable` (drag/resize/rotate/snap). `@dnd-kit` остаётся только для сортировки страниц.
- Состояние редактора: локальный редьюсер страницы + `editor-history`, без глобального стора; тяжёлые элементы мемоизируются, коммиты во время жеста — transient (без записи в историю).
- Формат листа: `PageFormat = { w, h, unit }`; A4 = 794×1123 px @96dpi, слайд = 1280×720. Всё остальное — общее.
- Схема БД не меняется: элементы кладутся в существующие JSON-поля `content` презентаций и документов.
- Риски: расхождение шрифтовых метрик браузер/PDF (закрываем существующим `text-metrics` и постраничным сравнением), большие старые документы (миграция покрыта юнит-тестами и обратимым фолбэком на старый рендер до первого сохранения).
