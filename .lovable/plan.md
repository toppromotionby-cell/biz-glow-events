# Ручное обучение ИИ-управленца + инструкция по API-ключам

## Что уже сделано в этой сессии

- `src/lib/copilot/teach.ts` — типы кандидатов в базу знаний, проверка файла (PDF, PNG/JPG/WEBP, TXT/MD/CSV/JSON, до 12 МБ), разбор JSON-ответа модели.
- `src/lib/copilot/teach.server.ts` — разбор документа мультимодальной моделью и запись утверждённых фактов в общую базу знаний (`scope: shared`, тег «обучение» + имя файла).
- `src/lib/copilot/copilot.functions.ts` — серверные функции `copilotTeachPreview` и `copilotTeachApprove` под тем же доступом, что и остальной копилот (только админ/операторы).

## Что осталось доделать

### 1. Вкладка «Обучение» на странице `/admin/copilot`

Новая вкладка рядом с «Планы / Аудит / Настройки»:

```text
[ Выбрать файл ]  документ.pdf · 1,2 МБ
[ Пожелание: на что обратить внимание (необязательно) ]
[ Разобрать документ ]
──────────────────────────────────────────────
Превью: заголовок + краткое резюме
☑ Тема факта            редактируемое поле
   Текст факта          редактируемое поле (textarea)
☑ ...                   (снять галочку — факт не сохранится)
──────────────────────────────────────────────
[ Утвердить и записать в базу знаний ]   [ Отменить ]
```

Поведение:
- файл читается в браузере: текстовые форматы — как текст, PDF и картинки — в base64;
- проверка типа и размера до отправки, понятные сообщения об ошибке;
- после «Утвердить» — тост «Записано N фактов», список очищается;
- сохранённые факты сразу доступны копилоту и обоим Telegram-ботам (общая база знаний).

### 2. Инструкция по API-ключам в админке

На странице `/admin/ai-providers` (раздел «Настройки → ИИ-провайдеры и роли») добавить блок «Как подключить бесплатные нейросети»: для каждого провайдера — где взять ключ, точное имя переменной и куда её вставить.

| Провайдер | Где взять ключ | Имя секрета |
| --- | --- | --- |
| Groq | console.groq.com/keys | `GROQ_API_KEY` |
| Google AI Studio | aistudio.google.com/apikey | `GEMINI_API_KEY` |
| OpenRouter | openrouter.ai/keys | `OPENROUTER_API_KEY` |
| Mistral | console.mistral.ai/api-keys | `MISTRAL_API_KEY` |
| GitHub Models | github.com/settings/tokens (classic, без прав) | `GITHUB_MODELS_TOKEN` |

В блоке — пошагово: открыть ссылку → зарегистрироваться → создать ключ → скопировать → передать разработчику/вставить в настройки секретов проекта → вернуться на страницу и нажать «Обновить статус» (зелёная плашка «Подключён»). Отдельно предупреждение: ключи не хранятся в коде и не видны в интерфейсе, вставлять их в поля на сайте не нужно. Такую же короткую подсказку продублировать ссылкой из Центра помощи сотрудника (`/admin/help`).

### 3. Автопроверки

- юнит-тесты `teach.ts`: приём/отказ по типу и размеру файла, разбор корректного и битого JSON, отсечение дублей и пустых фактов;
- тест `teach.server.ts`: сборка сообщений для модели (PDF → блок `file`, картинка → `image_url`, текст → в промпт);
- тест на то, что новая вкладка и страница провайдеров покрыты правилом доступа `system.manage`.

## Технические детали

- Файл передаётся на сервер как base64 в теле серверной функции; лимит 12 МБ совпадает с лимитом разбора скриншотов в ботах.
- Разбор идёт через ИИ-шлюз (`google/gemini-3.7-flash`, `response_format: json_object`); ошибки шлюза (429/402/403) переводятся на человеческий язык.
- Запись в базу знаний идёт через существующий `upsertFact` — дубликаты (схожесть ≥ 0.8 в той же теме) обновляются, а не плодятся.
