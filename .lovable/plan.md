# Что произошло

В журнале первая проверка `imap.hoster.by` упала через ~40 с с сообщением `This operation was aborted`. Сразу следующие проверки `imap.event-hub.by` отвечали за 1–2 с уже осмысленным `getaddrinfo ENOTFOUND`. Это классический симптом холодного старта воркера на Render free: первый запрос ждёт пробуждения инстанса (часто 30–50 с), а наш `AbortController` в `src/lib/mail-worker.server.ts` рубит fetch ровно на 30 с (`timeoutMs: 30_000` для `/test`). Сообщение «This operation was aborted» — это текст ошибки от `fetch`/`AbortSignal`, мы его прокидываем как есть в toast и в `sync_error`.

# Цель

Сделать кнопку «Проверить» устойчивой к холодному старту воркера и понятной по тексту ошибки.

# Что меняем (минимально, только клиент/серверные fn, без UI-переработки)

1. **`src/lib/mail-worker.server.ts`**
   - Увеличить дефолтный timeout `/test` до 90 с.
   - При `AbortError` бросать `MailWorkerError` с понятным сообщением: «Воркер не ответил за N сек (возможно, холодный старт). Повторите попытку.» и `status = 504`.
   - Перед фактическим вызовом `/test` делать быстрый прогрев: `GET /health` с таймаутом ~5 с (ошибки прогрева игнорируем). Это будит инстанс до основного запроса.
   - Один автоматический retry для `/test`, если первый ответ — таймаут/сеть (status 0/504) и пришёл быстрее 5 с после старта прогрева.

2. **`src/lib/mail.functions.ts` → `testMailAccount`**
   - Передавать в `callMailWorker('/test', cfg, { timeoutMs: 90_000 })`.
   - При таймауте писать в журнал `mail_account_checks` `status_code = 504` и сообщение «Воркер не ответил…», а не сырое `This operation was aborted`. `mail_accounts.status` — `error`, `sync_error` — то же читабельное сообщение.

3. **`src/routes/admin.mail-accounts.tsx`**
   - В `handleTest` ловить `status_code === 504` и в toast писать «Воркер просыпается, попробуйте ещё раз через 10–20 секунд» вместо «aborted».
   - Никаких визуальных перестроек.

# Что НЕ меняем

- Схемы, миграции, RLS, таблицы — без изменений.
- UI таблицы/диалогов аккаунтов и журнала проверок — без изменений (только текст toast).
- Воркер на Render не трогаем (это внешний сервис).

# Проверка

- Открыть `/admin/mail-accounts`, нажать «Проверить» на холодном воркере → ожидаем либо успешный ответ (после прогрева), либо понятный toast про «воркер просыпается», а не «aborted». В журнале `mail_account_checks` — запись с `status_code=504` и читаемым `message`.
- Повторная проверка через 5–10 с возвращает реальный результат IMAP/SMTP (как сейчас `getaddrinfo ENOTFOUND` для несуществующего хоста).
