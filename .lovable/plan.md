# DJ Hub — закрытый раздел для event-диджеев

Отдельный самостоятельный модуль на event-hub.by: публичная посадочная страница + закрытый клуб по приглашению с библиотекой треков, каталогом софта, плеером, рейтингами, фильтрами и обсуждениями. Управляется отдельной ролью админа, никак не пересекается с остальным сайтом (каталог, заказы, КП, документы работают как прежде).

## Что получит пользователь

**Публичная страница `/dj`** — витрина в стилистике сайта: тёмный герой с обещанием («закрытый пул для event-диджеев»), блоки «Что внутри» (треки, ремиксы/эдиты, софт и плагины, обсуждения), превью-карточки последних релизов без возможности скачивания, форма заявки на вступление. SEO-метатеги, микроразметка.

**Закрытый клуб `/dj/pool`** — доступен только участникам с одобренной заявкой:
- **Библиотека треков**: список/сетка с обложкой, артистом, названием, версией (Original / Extended / Clean / Dirty / Intro / Acapella), жанром, BPM, тональностью (Camelot), годом, энергией, датой добавления.
- **Плеер**: закреплённая внизу панель с волновой формой, очередью, перемоткой, регулировкой громкости, воспроизведением без остановки при переходах по страницам, горячими клавишами (пробел, стрелки).
- **Фильтры**: жанр, BPM-диапазон, тональность, версия, год, язык, «только новое за 7/30 дней», сортировка по дате/рейтингу/популярности, поиск по артисту и названию.
- **Рейтинг и реакции**: оценка 1–5 звёзд, счётчик прослушиваний и скачиваний, «в избранное», личные плейлисты/крейты.
- **Скачивание**: по одной или пачкой в выбранном качестве, с логированием, кто и что скачал.
- **Каталог софта**: DJ-программы и плагины с версией, датой релиза, платформой (Windows/macOS), размером, changelog, историей версий и инструкцией.
- **Обсуждения**: комментарии к треку и к софту, отдельная лента тем (заявки, вопросы, «ищу трек»), ответы веткой, уведомления автору.
- **Загрузки от участников**: проверенный DJ загружает трек/софт, заявка уходит на модерацию, автор видит статус.

**Админка `/admin/dj`** — отдельный раздел, видимый только новой роли:
- Модерация загрузок (одобрить/отклонить с причиной).
- Управление участниками: заявки на вступление, выдача статуса «проверенный DJ», блокировка.
- Библиотека: массовая загрузка, редактирование метаданных, пакетное проставление жанра/BPM/тональности, удаление.
- Каталог софта: версии и changelog.
- Модерация комментариев, жалобы.
- Статистика: топ треков, активность участников, объём хранилища.

## Роли и изоляция

Новая роль **`dj_admin`** («Администратор DJ-раздела»): доступ только к `/admin/dj`, ни к заказам, ни к документам, ни к настройкам. Существующий `admin` тоже видит раздел. Остальные роли — нет. Обратное тоже верно: `dj_admin` не получает ни одного текущего права.

Участники клуба — отдельный статус в таблице DJ-профилей (pending / approved / trusted / blocked), не роль в админке. Регистрация в клуб идёт по заявке, одобряет DJ-админ.

## Технический план

### База данных (одна миграция)
- `app_role` += `dj_admin`; в `permissions.ts` новое право `dj.manage`, матрица и `ROUTE_PERMISSIONS` для `/admin/dj`.
- `dj_members` — профиль участника (user_id, ник, город, статус, заметка админа, дата одобрения).
- `dj_tracks` — артист, название, версия, жанр, bpm, key_camelot, год, язык, длительность, теги, storage-путь аудио, путь превью-волны, обложка, статус (draft/pending/published/rejected), автор загрузки, счётчики прослушиваний/скачиваний.
- `dj_software` + `dj_software_versions` — продукт, платформа, версия, дата релиза, размер, changelog, storage-путь.
- `dj_ratings` (уникально user+track), `dj_favorites`, `dj_playlists` + `dj_playlist_items`.
- `dj_comments` — полиморфно к треку/софту/теме, ветки через parent_id, статус модерации.
- `dj_threads` — темы обсуждений.
- `dj_downloads` — журнал скачиваний (кто, что, когда).
- RLS: чтение опубликованного — только `approved`-участникам; вставка — trusted-участникам с принудительным `pending`; полное управление — `dj_admin`/`admin` через `has_role`. GRANT'ы на каждую таблицу в той же миграции.

### Хранилище
Приватные бакеты `dj-audio` (лимит ~100 МБ на файл), `dj-software` (~2 ГБ), публичный `dj-artwork` для обложек. Политики на `storage.objects` по членству. Выдача файлов — короткоживущими подписанными ссылками через серверные функции, никогда прямой публичной ссылкой на аудио.

### Серверные функции (`createServerFn`)
`src/lib/dj/*.functions.ts`: список треков с фильтрами и пагинацией, подписанный стрим-URL, скачивание с логом, рейтинг, избранное, плейлисты, комментарии, заявки, загрузка, модерация. Каждая проверяет членство/право на сервере через `requireSupabaseAuth` + `assertPermission`, не полагаясь на UI.

### Фронтенд
- Маршруты: `dj.tsx` (лендинг), `dj.pool.tsx`, `dj.track.$id.tsx`, `dj.software.tsx`, `dj.forum.tsx`, `dj.account.tsx`, `admin.dj.*`.
- Плеер как глобальный контекст внутри DJ-раздела (не на остальном сайте), волна — `wavesurfer.js`, генерация peaks при загрузке.
- Компоненты в `src/components/dj/` на существующих shadcn-примитивах и токенах темы сайта — без новых цветов вне дизайн-системы.
- Загрузка больших файлов — resumable-загрузка в storage с прогрессом и повтором.

### Проверки и качество
- Zod-валидация всех входов; ограничение типов файлов (mp3/wav/flac/aiff, zip/dmg/exe) и размера.
- Rate-limit на скачивания и загрузки, антифлуд на комментарии.
- Unit-тесты: матрица прав с новой ролью, фильтры/сортировка, парсер метаданных, RLS-сценарии.
- E2E-проверка: неавторизованный не получает подписанную ссылку; неодобренный участник не видит библиотеку; `dj_admin` не попадает в остальные разделы админки.

## Порядок работ

1. Миграция БД + бакеты + роль `dj_admin` в матрице прав.
2. Серверные функции и RLS-тесты.
3. Админка `/admin/dj`: участники, библиотека, модерация.
4. Клубная часть: библиотека, фильтры, плеер, рейтинг, избранное.
5. Софт и версии.
6. Комментарии и обсуждения.
7. Публичный лендинг `/dj` + SEO.
8. Загрузки от участников и модерация.
9. Финальный аудит доступа и производительности.

Монетизация (тарифы/оплата) в этот объём не входит — структура закладывается так, чтобы подписку можно было включить позже без переделки.
