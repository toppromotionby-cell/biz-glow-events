Проблема сейчас не в отображении fallback-страницы: она уже показывается. Реальный сбой остаётся в SSR главной страницы — запрос к `https://event-hub.by/` возвращает HTTP 500, а серверные логи показывают `h3 swallowed SSR error`. Наиболее вероятная зона: loader главной `src/routes/index.tsx` → `getHomeData()` → публичные server functions / backend-чтение.

План исправления:

1. Найти точную причину 500 на главной
   - Проверить loader главной страницы и все server functions, которые он вызывает.
   - Изолировать падение в `getHomeData()` и связанных публичных чтениях: каталог, кейсы, блог, рекомендации.
   - Усилить логирование так, чтобы в production-логах был не только generic `HTTPError`, а конкретная ошибка функции/запроса.

2. Починить источник SSR-падения
   - Убрать хрупкое поведение, при котором ошибка загрузки рекомендаций/кейсов/блога валит всю главную страницу.
   - Сделать `getHomeData()` fail-soft: если один блок не загрузился, главная всё равно рендерится с пустым блоком, а ошибка пишется в логи.
   - Проверить публичные server functions на небезопасные top-level server-only импорты и при необходимости перенести backend-клиент внутрь handler/server-only helper, чтобы production SSR не падал на инициализации модулей.

3. Сделать Error Boundary полезным, а не финальным экраном для посетителя
   - Оставить единый 404/500 fallback, но заменить англоязычную системную страницу на брендированную русскую HTML-страницу для catastrophic SSR.
   - Для клиентских ошибок сохранить кнопки “Попробовать снова” и “На главную”, чтобы навигация не ломалась.

4. Добавить автоматическую проверку регрессий
   - Расширить health/smoke-проверку так, чтобы она проверяла `/`, основные разделы и `/api/public/health` именно на отсутствие 500.
   - В админском баннере показывать красный статус, если главная или ключевые разделы снова отдают 500.
   - Сделать fallback главной устойчивым: даже при временной ошибке backend-чтения сайт не должен показывать “This page didn’t load”.

5. Проверка после исправления
   - Проверить `https://event-hub.by/` и ключевые страницы: `/zones`, `/equipment`, `/services`, `/production`, `/cases`, `/blog`, `/contacts`.
   - Убедиться, что главная возвращает 200 и открывается без fallback-экрана.
   - Проверить production-логи: новых `[ssr-error] GET /` быть не должно.

После подтверждения внесу изменения и проверю результат на опубликованном домене.
