## Цель

В админ-редакторе каталога (zones / tech_equipment / services / production_items) поле «Категория» сейчас — обычный `Input`. Заменить на combobox, который:
- выбирает строго из существующих категорий,
- позволяет добавить новую,
- позволяет удалить ненужную,
- не нагружает публичную часть сайта.

## Решение

Завести отдельный справочник `catalog_categories` (по одному списку на тип каталога) и UI-компонент `CategoryCombobox`. Поле `category` на самих позициях остаётся текстом — это loose coupling: переименование/удаление справочной записи не ломает данные, а просто перестаёт предлагать её в подсказках.

### 1. Миграция БД

Новая таблица:

```text
catalog_categories
  id           uuid pk
  entity_type  text   -- 'zones' | 'tech_equipment' | 'services' | 'production_items'
  name         text
  sort_order   int    default 0
  created_at   timestamptz default now()
  unique (entity_type, lower(name))
```

RLS:
- `SELECT` — только authenticated (admin / content_editor). Публично читать справочник не нужно: фронт уже показывает категории через сами позиции каталога.
- `ALL` — admin / content_editor (то же правило, что для самих каталогов).

Backfill одним SQL: `INSERT ... SELECT DISTINCT category, entity_type FROM каждая_таблица WHERE category IS NOT NULL ON CONFLICT DO NOTHING`. Не задевает существующие данные, просто наполняет справочник тем, что уже есть.

### 2. Компонент `CategoryCombobox`

`src/components/admin/CategoryCombobox.tsx` — на базе shadcn `Popover + Command`:
- Триггер показывает текущее значение или «Выбрать категорию».
- Внутри: поиск, список категорий с иконкой «✕» (удалить, с подтверждением), внизу — строка «+ Добавить “{query}”», появляется, когда введённый текст не совпадает ни с одной записью.
- Выбор — `onChange(name)`; на самой позиции по-прежнему хранится строка.
- Данные тянутся через TanStack Query: `useQuery(['catalog-categories', entityType])`. Запрос идёт только когда открыт редактор админки → на публичных страницах ноль трафика.
- Мутации (`create` / `delete`) инвалидируют кэш этого ключа.

### 3. Интеграция

В `src/routes/admin.catalog.$type.tsx` заменить строку с `<Field label="Категория"><Input .../></Field>` на `<CategoryCombobox entityType={table} value={form.category} onChange={(v) => setForm({ ...form, category: v })} />`. Больше ничего на странице не трогаем: сохранение/чтение позиций не меняется.

### 4. Что не делаем (намеренно)

- Никакого FK с `ON DELETE` — это вызвало бы каскадные правки и блокировки. Категория — это «тег»; удаление в справочнике просто убирает её из подсказок, существующие позиции с этим текстом продолжают работать (и админ в любой момент может выбрать им другую категорию).
- Не выносим справочник на публичный API и не подгружаем в бандл клиента — только в админских роутах.
- Не трогаем серверные функции каталога (`zones.functions.ts` и т.д.): они и так возвращают `category` как строку.

### 5. Опционально (если потребуется потом)

- Кнопка «Переименовать» в combobox — отдельной мутацией, плюс `UPDATE <table> SET category = new WHERE category = old` тем же тиком. Сейчас не нужно — не было в запросе.
- Фасетный фильтр по категориям на публичных страницах брать тоже из этого справочника вместо `DISTINCT` по позициям (быстрее и стабильнее), но это уже следующий шаг.

## Порядок реализации

1. Миграция (таблица + RLS + backfill).
2. `CategoryCombobox` + хуки запросов.
3. Подключить в админке вместо `Input`.
4. Проверить на каждом из 4 типов каталога: выбор, добавление, удаление, сохранение позиции.
