# Картинки не попадают в PDF: причина и починка

## Что проверено (факты, не догадки)

В базе у слайдов презентации сейчас лежат такие картинки:

- фото зоны `...photo-...-2.png` — на самом деле это JPEG-байты (проверено загрузкой), такой файл встраивается нормально;
- два логотипа `...-logo.svg` — **SVG**.

Общий загрузчик картинок для всех PDF (`src/lib/documents/image-embed.server.ts`) умеет встраивать только PNG и JPEG. Для «неподдерживаемых» форматов он пробует конвертацию:

- для ссылок нашего хранилища — только встроенный трансформер картинок;
- для внешних ссылок — публичный image-прокси.

Проверено вживую:

- трансформер хранилища на SVG **отдаёт тот же SVG** (`content-type: image/svg+xml`), конвертации не происходит → байты не распознаются → картинка молча пропадает;
- публичный прокси тот же SVG **успешно** превращает в растр (JPEG 21 КБ, ответ 200).

Итог: любая SVG-картинка (в презентациях это и слайды, и логотипы; то же самое в КП и договорах) не попадает ни в PDF, ни в его превью, потому что для файлов из нашего хранилища прокси вообще не пробуется, а собственный трансформер SVG не конвертирует. Растровые фото при этом работают.

## Что сделаю

1. Научу загрузчик распознавать SVG (по содержимому файла, а не по расширению) и сразу отправлять такие картинки на конвертацию в растр, минуя бесполезный для SVG трансформер хранилища.
2. Сделаю цепочку попыток общей для всех ссылок: трансформер хранилища → публичный прокси. Сейчас для файлов хранилища прокси не пробуется вообще, поэтому любая осечка трансформера означает потерю картинки.
3. Для логотипов и других картинок с прозрачностью буду просить у прокси PNG, чтобы прозрачный фон не превращался в белый прямоугольник; для фотографий останется JPEG (меньше вес).
4. Если после всех попыток растр получить не удалось — поведение прежнее: аккуратная плашка вместо фото, документ не падает.
5. Проверю сборку PDF презентации с реальными данными (SVG-логотип + фото) и посмотрю страницы глазами, чтобы убедиться: картинки на месте, кириллица не «квадратиками», композиция не разъехалась.

## Что останется без изменений

- Админка, каталог, публичный сайт, загрузка медиа и превью слайдов в браузере — там SVG и так отображается.
- Разметка и вёрстка PDF: меняется только получение байтов картинки.
- КП, промо-КП и договоры используют тот же загрузчик, поэтому у них SVG-логотипы тоже начнут печататься — это исправление, а не изменение поведения.
- База данных и серверные функции сохранения не трогаются.

## Технические детали

- `src/lib/documents/image-embed.server.ts`:
  - `sniffImageFormat` дополняется распознаванием `svg` (в том числе с BOM и XML-прологом);
  - `loadEmbeddableImageBytes` получает единый список кандидатов: `storageTransformUrl` (только для растра из хранилища) и `proxyUrl` с параметром `output=png|jpg`;
  - для исходников `svg`/`avif` с прозрачностью — `output=png`, иначе `jpg`;
  - результат каждой попытки по-прежнему проверяется сигнатурой файла.
- Тесты `src/lib/documents/__tests__/image-embed.test.ts`: распознавание SVG, порядок кандидатов и выбор формата вывода, поведение при полном отказе (возврат `null`).
- Ручная проверка: сборка PDF презентации через существующий рендер и просмотр страниц как изображений.
