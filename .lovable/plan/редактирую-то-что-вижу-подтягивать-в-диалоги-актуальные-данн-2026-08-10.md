# «Редактирую то, что вижу»: подтягивать в диалоги актуальные данные превью

При двойном клике по блоку в превью часть полей открывается пустой, хотя в документе текст есть. Причина найдена: диалог берёт `block.content`, и когда у блока своего текста нет, а превью показывает унаследованный текст из `quote.texts` (или из общих настроек документов), поле остаётся пустым. Пример со скриншота: «Вступительный текст» пуст, хотя в превью абзац «Благодарим за интерес…» отображается.

## Что делаем

**1. Единая функция «эффективного значения»**

Для каждого блока считаем ровно то, что рисует превью, и этим заполняем форму:
- обложка: заголовок документа (или дефолт «Предложение по организации мероприятия») + вступление из блока → из `texts.intro`;
- текстовые блоки (что входит / не входит / сроки / условия): содержимое блока → запасной текст из `texts.*`;
- подвал и примечание об НДС: своё значение → значение из общих настроек документов (уже работает, приводим к общей логике);
- реквизиты КП: поля показывают унаследованные значения компании как подсказку-плейсхолдер и как отправную точку для правки.

Правило: пустая строка тоже считается «нет значения» — то есть подставляем унаследованное (сейчас используется `??`, который на пустой строке не срабатывает).

**2. Показ подставленного текста плейсхолдеров**

Под полями с плейсхолдерами (`{{client_name}}` и т.п.) выводим строку-предпросмотр «Как будет в документе: …», чтобы было видно итоговый текст, как в превью.

**3. Итоги: показываем реальные суммы**

В диалоге «Итоги и оплата» добавляем сводку только для чтения, рассчитанную тем же кодом, что и превью: стоимость позиций, скидка, доставка, база без НДС, НДС, ИТОГО, предоплата, остаток. Значения пересчитываются на лету при изменении скидки/предоплаты/НДС в этом же окне.

**4. Позиция и раздел**

- В диалоге позиции показываем сумму строки (кол-во × цена) и, если задана себестоимость, маржу — как в таблице превью.
- В диалоге раздела — количество позиций и сумму по разделу.

**5. Шапка документа**

Если номер не задан вручную, поле показывает подсказку с автономером, который виден в превью, и вычисленную дату «действительно до».

**6. То же самое для КП промо**

В диалоге промо-КП: пустые поля шапки заполняются фактическими значениями документа, в «Итогах» появляется сводка (позиции, скидка, комиссия, менеджмент, НДС, итого), в позиции — сумма строки с учётом множителя.

**7. Сквозная проверка**

Проходим по всем целям редактирования (`header`, `company`, `cover`, `client`, `event`, `item`, `section`, `totals`, `block`, `footer` и промо-аналоги) и сверяем: что показывает превью — то и лежит в полях при открытии.

## Технические детали

- `src/lib/documents/quote-html.ts` — экспортируемый `blockText` переиспользуем в диалоге; при необходимости выносим `effectiveBlockContent` рядом.
- `src/components/admin/documents/BlockEditDialog.tsx` — инициализация `draft` через «эффективные» значения (замена `??` на проверку непустой строки), сводка итогов через тот же `computeTotals`, предпросмотр плейсхолдеров.
- `src/components/admin/documents/PromoBlockEditDialog.tsx` — аналогично, расчёт через существующие функции модели промо-КП.
- Расчёты берём из общих модулей (`computeTotals`, модель промо-КП), новых формул не заводим — чтобы диалог и превью не разошлись.
