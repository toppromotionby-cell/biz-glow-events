# Предпродакшн-аудит: переходы, фильтры, вкладки, боты

Цель — пройти весь сайт и админку, найти битые переходы, неверные фильтры и вкладки, починить и закрыть автопроверками, чтобы такое не повторилось.

## 0. Сначала — блокирующая ошибка сборки

В матрице прав для `/admin/assistant` указано несуществующее право `settings.manage`. Заменить на `system.manage` (раздел ассистента = системные настройки). Без этого проект не собирается.

## 1. Целостность ссылок и маршрутов

- Собрать карту всех `<Link to=...>`, `href="/..."`, программных `navigate({ to })` и пунктов меню/сайдбара.
- Сверить с реальными файлами маршрутов (112 файлов в `src/routes`): найти ссылки на несуществующие пути, ссылки с параметрами без `params`, интерполяцию вида `` `/path/${id}` `` вместо `params`.
- Починить найденное; заменить оставшиеся `<a href="/...">` на `<Link>`.
- Автопроверка: тест, который парсит исходники и падает, если ссылка не резолвится в маршрут или динамический сегмент не покрыт `params`.

## 2. Фильтры, вкладки и состояние в URL

Проверяемые места: каталоги (`/zones`, `/equipment`, `/services`, `/production`), `/dj/pool`, кейсы, блог, списки админки (заказы, документы, каталог, paperwork, аудит, ассистент).

- Каждый маршрут с фильтрами должен иметь `validateSearch` с дефолтами, чтобы «мусорные» параметры из рекламы не ломали страницу.
- Двусторонняя синхронизация: клик по плашке меняет URL, открытие URL восстанавливает состояние, сброс очищает параметры.
- Переход из меню/плашки в нужную вкладку и нужную категорию (проверить активное состояние и подсветку).
- Пустая выдача — показывает понятный пустой экран, а не «сломанную» страницу.
- Для отфильтрованных страниц — корректный canonical и `noindex` там, где нужно.
- Автопроверка: тест на дефолты/парсинг `search` + браузерный сценарий «кликнул фильтр → URL → перезагрузка → то же состояние».

## 3. Админка: доступы, меню, вкладки

- Каждый путь `/admin/*` должен иметь право в матрице и пункт в меню (тест уже есть — расширить: и обратная сторона, пункт меню не должен вести в никуда).
- Прогон по ролям (админ, менеджер, бухгалтер, контент-редактор, DJ-админ): нет ссылок на разделы, куда роль не пустят; редирект недоступного раздела ведёт на разрешённый.
- Проверить вкладки/табы внутри разделов (документы, paperwork, DJ, ассистент): активная вкладка совпадает с URL, deep-link открывает нужную.

## 4. Прогон живых страниц

Скриптовый обход публичных страниц и ключевых страниц админки на ширинах 390 / 768 / 1440:

- HTTP 200 и отсутствие ошибок в консоли и в SSR-логах;
- есть один `h1`, уникальные title/description;
- нет горизонтального переполнения, ключевые кнопки кликабельны;
- формы (заявка, корзина, логин) отправляются и дают понятный результат.

Все найденные критические дефекты чиню в этом же прогоне.

## 5. Telegram-боты и связанные механики

- Проверить регистрацию вебхуков всех трёх ботов, наличие токенов, ответ на `/start` и `/help`.
- Проверка форматирования: ни один ответ не должен содержать «сырые» теги — расширить существующий гард на все точки отправки.
- Кнопки «Отправить в Telegram» из документов/КП/презентаций: файл реально уходит, ошибки видны пользователю.
- Уведомления об ошибках доступа Google (календарь/задачи) приходят и не спамят.

## 6. Единая команда проверки

Собрать все гарды в одну команду (`bun run verify`): типы, юнит-тесты, гард дизайна, гард ссылок, гард прав, гард форматирования ботов и браузерный смоук. Её же прогонять перед каждым релизом.

## Технические детали

- Гарды — статические тесты по исходникам (`src/**/*.tsx`) в `src/lib/__tests__/`, плюс браузерные сценарии на Playwright в отдельном скрипте.
- Карта маршрутов берётся из имён файлов в `src/routes` (правила dot→slash, `index`, `$param`, `_layout`), без правки `routeTree.gen.ts`.
- Правки по фильтрам делаются через `validateSearch` + `Route.useSearch()` и `navigate({ to: ".", search: (prev) => ... })`, без ручного разбора `window.location`.

## Что получите

Отчёт со списком найденных проблем и исправлений, плюс набор автопроверок, который падает при повторном появлении битой ссылки, неработающего фильтра, недоступной вкладки или сломанного ответа бота.
