# Автосохранение по всей админке + проверки

Цель: во всех разделах админки правки сохраняются сами, статус сохранения выглядит одинаково, изменённые данные сразу видны везде (списки, публичная часть), а автотесты не дают это сломать.

## Что сейчас есть и чего не хватает

Автосохранение (или хотя бы черновик + защита от ухода) есть в: КП, промо-КП, презентации, кейсы, отзывы, блог, заказы (внутренние заметки, оплата), акции, каталог, настройки документов, профиль.

Автосохранения нет — только кнопка «Сохранить» или молчаливое сохранение:
- Настройки → Соцсети (`admin.settings.social`)
- Настройки → Письма (`admin.settings.emails`)
- Структура каталога (`admin.catalog-structure`)
- Корпоративные документы и шаблоны (`PaperworkEditor`, шаблоны)
- Почтовые аккаунты (`admin.mail-accounts`)
- База знаний документов (`admin.documents.knowledge`)
- Видимость секций (`admin.sections`) — сохраняет по переключателю, но без общего статуса и без сброса кэша публичной части
- Пользователи (`admin.users`) — ролевые действия, автосохранение не нужно, нужна проверка обновления списка

## Что будет сделано

### 1. Единый механизм автосохранения
- Все перечисленные редакторы переводятся на общий хук `useEditorSave` (задержка 1.2 с, Ctrl+S, статус, защита от ухода со страницы) и общий индикатор `SaveStatus` — одинаковый текст «Сохранено в 15:40 / Сохраняем… / Есть несохранённые правки».
- Кнопка «Сохранить» остаётся везде как ручной дубль и просто вызывает немедленное сохранение.

### 2. Чувствительные разделы — без автоотправки
Для почтовых аккаунтов (логины/пароли/SMTP) и шаблонов писем автосохранения на сервер не будет: локальный черновик + предупреждение при уходе + явная кнопка «Сохранить». Это защищает от случайной поломки рабочей почты и рассылок.

### 3. Данные видны везде после правки
- Единый список ключей кэша: после каждого сохранения сбрасываются и админ-список, и связанные публичные запросы (навигация каталога, настройки сайта, видимость секций, каталожные страницы).
- Раздел «Видимость секций» после переключателя обновляет публичные настройки — изменения видны на сайте без перезагрузки.
- Структура каталога после сохранения обновляет навигацию и страницы каталога.
- Корпоративные документы после сохранения обновляют список и превью документа.

### 4. Автоматические проверки
- Юнит-тесты на общий слой: статус сохранения, дебаунс, докат правки при закрытии редактора, набор сбрасываемых ключей кэша.
- Smoke-тест по всем редакторам админки: перебирает файлы редакторов и падает, если у редактора нет автосохранения/черновика, нет индикатора статуса, нет защиты от ухода или нет сброса кэша после сохранения. Новый редактор без этих элементов не пройдёт проверку.

- Общие модули: `src/hooks/use-editor-save.ts`, `src/lib/editor/save-state.ts`, `src/hooks/use-unsaved-guard.tsx`, `src/lib/admin/use-autosave-draft.ts` — переиспользуются, API не меняется.
- Новый модуль `src/lib/admin/invalidate.ts`: карта «сущность → список ключей запросов» (админские + публичные), одна функция `invalidateEntity(qc, entity)`; переводим на неё сохранения в затронутых экранах.
- Правки в: `admin.settings.social.tsx`, `admin.settings.emails.tsx`, `admin.catalog-structure.tsx`, `admin.sections.tsx`, `admin.documents.knowledge.tsx`, `admin.mail-accounts.tsx`, `components/admin/paperwork/PaperworkEditor.tsx` (+ шаблоны paperwork).
- Тесты: `src/lib/admin/invalidate.test.ts`, расширение `src/routes/__tests__/admin-editors.smoke.test.ts` (статический разбор файлов редакторов по списку обязательных признаков), дополнение `src/lib/editor/__tests__/save-state.test.ts`.
- Логика сохранения данных и схемы БД не меняются — только слой UI/состояния и инвалидация кэша.
