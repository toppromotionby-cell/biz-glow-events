# Разделы и направления: управление, скрытие, автоочистка

## Что получит администратор

В админке «Разделы и направления» появится один экран управления структурой каталога:

1. **Свои (виртуальные) разделы.** Можно создать собственный раздел-витрину (например, «Новый год» или «Свадьбы»), задать название, описание, иконку, адрес и выбрать, какие направления из существующих разделов в него попадают. Такой раздел появляется в меню «Каталог», на странице каталога и в блоке направлений на главной — в том же стиле, что и остальные плитки. Его можно удалить в любой момент, позиции при этом не трогаются.
2. **Базовые разделы** (Зоны, Техника, Услуги, Продакшн, Аттракционы) остаются, но ими можно управлять: переименовать, изменить описание/иконку, порядок и переключатель «Показывать». Удалить их нельзя — вместо этого выключение.
3. **Скрытие для редко используемых.** У каждого раздела и направления есть переключатель видимости. Скрытые собираются внизу в свёрнутом блоке «Скрытые (N)», чтобы не мешать ежедневной работе. Есть поиск по названию и счётчик позиций у каждой строки.
4. **Автоматическая синхронизация с карточками.** Направление, в котором не осталось ни одной позиции, удаляется автоматически. Так же удаляются направления, чей раздел больше не существует. Для только что созданных направлений действует защитный период 24 часа, чтобы новое направление не исчезло до того, как в него добавят первую карточку. Виртуальный раздел, в котором не осталось ни одного живого направления, автоматически скрывается с сайта (в админке остаётся, чтобы его можно было донастроить).

Очистка запускается: при открытии страницы структуры, после сохранения/удаления карточки каталога и при построении меню — то есть меню на сайте всегда соответствует фактическому наполнению.

## Технические детали

**База данных (миграция)**
- `catalog_sections`: добавить `kind text not null default 'native'` (`native` | `virtual`), `slug text unique`, `category_ids uuid[] not null default '{}'`, `auto_hidden boolean not null default false`.
- Разрешить INSERT/DELETE для виртуальных разделов в RLS-политиках (админ/менеджер), базовые (`kind = 'native'`) защитить от удаления триггером.
- GRANT по правилам проекта.

**Сервер**
- Новый `src/lib/catalog-structure.functions.ts` (server fns, `requireSupabaseAuth` + проверка роли): `createVirtualSection`, `updateSection`, `deleteVirtualSection`, `reorderSections`, `cleanupCatalogStructure`.
- `cleanupCatalogStructure`: считает опубликованные позиции по `category` в таблицах разделов, удаляет направления с нулём позиций старше 24 часов и «сиротские» направления, выставляет `auto_hidden` виртуальным разделам без живых направлений. Возвращает отчёт (что удалено/скрыто) для тоста в админке.
- `getCatalogNavigation` в `src/lib/catalog-nav.functions.ts`: возвращать виртуальные разделы (агрегат по `category_ids`), учитывать `auto_hidden`, дергать лёгкую версию очистки не чаще раза в N минут.

**Фронт**
- `src/routes/admin.catalog-structure.tsx`: переработка — поиск, счётчики позиций, блок «Скрытые», кнопка «Создать раздел» (диалог: название, описание, иконка, адрес, выбор направлений), кнопка «Проверить и очистить» с отчётом.
- `src/lib/catalog-nav.functions.ts` + `CatalogNav.tsx`/`CatalogSectionTile`: поддержка `basePath` вида `/catalog/<slug>` для виртуальных разделов.
- Новый маршрут `src/routes/catalog.$slug.tsx` — витрина виртуального раздела: сетка `grid-cards`, фильтры по входящим направлениям, `head()` с уникальными title/description/og.
- Вызов очистки после сохранения/удаления карточки в редакторе каталога.

## Проверка
- Сборка и типы.
- Playwright: создание виртуального раздела → появление плитки в мега-меню, на `/catalog` и на главной; скрытие раздела → исчезает с сайта; удаление последней позиции направления → направление пропадает после очистки.
