# Полный перенос данных КП в Google Таблицы и Google Документы

Сверил превью КП (`promo-quote-html.ts`) с выгрузками. Часть содержимого до Google действительно не доезжает.

## Что сейчас теряется

| Что есть в превью/PDF | Google Таблица | Google Документ |
|---|---|---|
| Состав позиции (подпункты «включено» под наименованием) | нет | нет |
| Логотип компании и логотип клиента | нет | есть |
| Строка реквизитов компании | берётся не из того поля — часто пустая | есть |
| Прочерки «—» в служебных строках (управление, комиссия, НДС) | пустые ячейки | пустые ячейки |
| Ставка комиссии в колонке «Примечания» | есть | есть |
| Примечание внизу документа | есть | есть, но ошибочно оформлено как итог (жирным и по правому краю) |
| Валюта в строке «Итого» | есть | есть |
| Плейсхолдер «Позиции не добавлены» для пустого КП | нет | нет |

## Что сделаю

1. **Общий макет** (`doc-layout.ts`) — единственный источник данных для обеих выгрузок:
   - добавлю в строку позиции текст состава (подпункты «включено»), если он включён в настройках КП;
   - заполню прочерки «—» в служебных строках, как в превью;
   - добавлю служебные поля: строка реквизитов, ссылки на логотипы, примечание, плейсхолдер пустой таблицы.
2. **Google Таблица**: строка реквизитов из корректного поля, состав позиции в ячейке наименования (перенос строки, авто-высота), логотипы над шапкой (через `=IMAGE()`), прочерки, плейсхолдер.
3. **Google Документ**: состав позиции отдельным абзацем в ячейке (мельче и серым), прочерки, примечание оформляется как примечание, а не как итог.
4. **Обратное чтение**: парсеры обеих выгрузок будут отбрасывать строки состава и служебные строки, чтобы правки из Google по-прежнему корректно возвращались в админку.

## Технические детали

- `src/lib/documents/doc-layout.ts` — расширяю `DocRow` полем `includes: string[]` и добавляю в `DocLayout` поля `companyLine`, `logos`, `footerNote`, `emptyLabel`.
- `src/lib/promo-sheets.server.ts` — реквизиты из `quote.company_line`; состав дописывается в ячейку `title` через `\n` + `wrapStrategy: WRAP`; логотипы вставляются формулой `IMAGE` в строку над номером КП; в `readPromoRows` состав срезается по первому переводу строки.
- `src/lib/documents/promo-gdocs.server.ts` — состав вставляется дополнительным абзацем в ячейку с уменьшенным кеглем; хвост документа разделяется на блок итогов (жирный, по правому краю) и примечание (обычный, по левому); `readPromoDocRows` берёт только первую строку ячейки наименования.
