# Слайд «закрывается» при редактировании — причина и починка

## Что происходит

В редакторе презентации включено автосохранение: через 3 секунды после последней правки данные уходят на сервер, а затем запрос презентации перезагружается. Когда свежие данные приходят, редактор целиком заменяет локальный список слайдов серверным — и выбранный слайд «слетает»: справа появляется «Слайд не выбран», по центру — «Выберите слайд в списке». Именно это видно на скриншоте (сохранено в 10:10, три слайда, ни один не выбран).

Причина: у только что добавленного слайда локальный временный идентификатор (`new-…`), а после сохранения сервер возвращает его уже с постоянным идентификатором. Выбор остаётся указывать на исчезнувший временный идентификатор, поэтому выбранного слайда больше нет.

Побочный эффект той же перезагрузки: если продолжать печатать в момент сохранения, ответ сервера затирает набранное — правки визуально «откатываются».

## Что будет сделано

1. Сохранять выбор при обновлении данных: если выбранный слайд исчез (сменился идентификатор), выбирать слайд на той же позиции, а не сбрасывать выбор. Для только что созданных слайдов сопоставлять временный идентификатор с постоянным по порядку слайдов после сохранения.
2. Не затирать текущие правки ответом сервера: обновлять локальное состояние из ответа только когда нет несохранённых изменений и не идёт сохранение; иначе просто подтверждать идентификаторы слайдов.
3. Убрать лишнюю перезагрузку после автосохранения — обновлять список презентаций, но не перезапрашивать открытую презентацию при каждом автосохранении.
4. Дополнительно: если слайдов больше нуля, а выбранного нет, автоматически выбирать первый — редактор никогда не остаётся в состоянии «Слайд не выбран».

## Технические детали

- Файл: `src/routes/admin.documents.presentations.$id.index.tsx`.
- Эффект синхронизации `data → meta/slides` получает охрану по `dirty` / `save.isPending`; после успешного сохранения выполняется сопоставление `new-*` идентификаторов с возвращёнными по индексу позиции и обновление `selected`.
- `savePresentation` уже возвращает результат сохранения; переиспользуем его вместо `invalidateQueries(["presentation", id])`, оставляя инвалидацию только для списка `["presentations"]`.
- Схема БД и серверные функции не меняются.

## Проверка

Открыть презентацию, добавить слайд, править текст и дождаться автосохранения: слайд остаётся выбранным, текст не откатывается, ошибок в консоли нет.
