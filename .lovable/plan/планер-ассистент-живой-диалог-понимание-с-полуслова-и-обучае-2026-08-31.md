# Планер-ассистент: живой диалог, понимание с полуслова и обучаемость

## Что не так сейчас

- Намерение определяется набором регулярок: шаг влево от шаблона («перенеси Иванова на пятницу», «сколько у меня встреч на неделе», «отмени вчерашнюю») — и ассистент вместо действия создаёт новую задачу.
- Диалога нет: если бот задал уточняющий вопрос («на когда поставить?»), ваш ответ «на 15:00» он считает новой задачей с названием «на 15:00». Каждое сообщение живёт отдельно.
- Умеет мало: создать, показать список, отметить сделанным, найти. Нет переноса, редактирования, удаления голосом, повторяющихся дел, заметок к записи, отмены последнего действия.
- Ответы сухие и одинаковые — просто перечисление строк, без группировки по времени/направлению, без итога дня и подсказки «с чего начать».
- Обучаемости нет: поле «стиль» есть, но никто его не заполняет; бот не запоминает ваши сокращения («Кузнец» = конкретный человек, «зал» = площадка), привычное время, длительности и типовые формулировки.

## Что делаем

### 1. Мозг на инструментах вместо регулярок
Ассистент переводится на модель с function-calling: она сама решает, что вы хотите, и вызывает нужный инструмент. Регулярки остаются только быстрым коротким путём для команд `/today` и однословных «сегодня/завтра» (мгновенный ответ без затрат).

Набор инструментов: создать, перенести, изменить (название, время, длительность, направление, важность, место, участники), отметить сделанным, вернуть в работу, удалить, показать период, найти, показать свободные слоты, добавить заметку, разбить на шаги, повторяющееся дело, отменить последнее действие, запомнить факт/предпочтение.

### 2. Память диалога
Каждый чат получает короткую историю (последние ~15 реплик, окно 30 минут) и «фокус» — запись, о которой сейчас идёт речь. Тогда работают цепочки:
«запиши встречу с подрядчиком» → «на когда?» → «завтра в 15» → «готово» → «сделай её жёсткой» → «перенеси на 17».

### 3. Обучаемость
Новая память ассистента трёх типов:
- **Словарь**: «Кузнец» → Кузнецов Пётр, «ТП» → Top Promotion, «зал» → площадка на Немиге.
- **Привычки**: типичная длительность встречи, рабочие часы по направлениям, любимые формулировки — копятся автоматически из ваших правок (перенесли — бот запомнил).
- **Правила от вас**: «называй меня Дмитрий», «не пиши эмодзи», «утренний дайджест в 8:30», «встречи по EventHub всегда 2 часа» — говорите обычной фразой, бот подтверждает: «Запомнил».

Всё это подмешивается в каждый запрос к модели, поэтому со временем бот угадывает всё точнее. Память видна и редактируется в админке (`/admin/planner` → Настройки → «Что бот обо мне знает»), любой пункт можно удалить.

### 4. Понятные ответы вместо простыни
- Списки группируются по частям дня (Утро / День / Вечер) и помечаются направлением цветной точкой, просроченное — отдельным блоком сверху.
- В конце дня — итог: «5 дел, 2 жёстких, 1 просрочено. Начните с …».
- Под каждой записью кнопки: Сделано / Перенести / +1 час / Изменить / Удалить. Плюс кнопка «Показать ещё», если записей больше 10.
- Подтверждение создания в человеческом тоне и с проверкой накладок (уже есть, оставляем).
- Тон настраивается: сухой / дружеский / с юмором — по вашему выбору в настройках или фразой в чате.

### 5. Голос — на равных с текстом
- Мгновенная реакция «слушаю…», затем показ распознанного текста с кнопкой «Не то → исправить» (правка тут же уходит в словарь и улучшает распознавание имён).
- Одно голосовое = несколько дел: «завтра в 10 встреча, потом позвонить Ивану, и до пятницы отчёт» → три записи, одно подтверждение списком.
- Ответы на голос дублируются короткой голосовой репликой (озвучка через сервис синтеза) — по желанию, включается в настройках.

### 6. Ничего не теряется
- Если модель недоступна или не поняла — сообщение всё равно сохраняется в «Входящие» с кнопкой «Разобрать позже», а не теряется в чате.
- «Отмени» откатывает последнее действие бота.
- Раздел «Входящие» в админке показывает всё, что бот не смог разобрать, с ручной доводкой в один клик — и эти правки тоже становятся обучающими примерами.

## Технические детали

- **Данные**: миграция добавляет `assistant_memory` (тип, ключ, значение, источник, вес, дата), `assistant_dialog` (chat_id, роль, текст, focus_item_id, ttl), `assistant_actions` (журнал действий для «отмени»); расширение `assistant_prefs` полями тона ответа и озвучки. Для всех таблиц — RLS + GRANT (доступ только `service_role` и админам через существующую роль-функцию).
- **Мозг**: `src/lib/calendar/brain.server.ts` — цикл tool-calling на AI SDK через Lovable AI Gateway (`google/gemini-3.7-flash` для быстрых ответов, эскалация на `google/gemini-3.1-pro-preview`, если модель не уверена), `stopWhen: stepCountIs(50)`. Инструменты в `src/lib/calendar/tools.server.ts` поверх существующего `store.server.ts` — новых путей к базе не заводим.
- `assistant.server.ts` остаётся единым входом для Telegram и Алисы: сначала быстрый детерминированный путь (команды), иначе — brain. Существующие тесты намерений сохраняются.
- **Память**: `memory.server.ts` — чтение/запись фактов, компакция (не больше ~60 активных записей, лишнее сжимается моделью в сводку).
- **Рендер**: `render.ts` — единый форматтер списков/карточек для Telegram (HTML + inline-кнопки) и для голоса (плоский текст, без разметки).
- **Тесты**: юнит-тесты на детект команд, разбор цепочки уточнений, слияние памяти и на форматтеры; мок AI-слоя, чтобы тесты не ходили в сеть.
- Ошибки шлюза (402/403/429) показываются человеческим текстом, сообщение сохраняется во «Входящие», авто-ретраев в цикле нет.

## Порядок работ

1. Миграция таблиц памяти/диалога/действий + расширение настроек.
2. Слой инструментов поверх store и журнал действий («отмени»).
3. Brain с tool-calling + память диалога, подключение к Telegram и Алисе.
4. Новый рендер ответов, кнопки, группировка, итоги дня.
5. Голос: подтверждение распознавания, мультизадачи, опциональная озвучка.
6. Память/обучение: авто-выводы из правок, команда «запомни», UI в админке.
7. Входящие с ручным разбором + тесты и проверка в реальном боте.
