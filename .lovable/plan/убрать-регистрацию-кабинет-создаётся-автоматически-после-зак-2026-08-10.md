# Убрать регистрацию: кабинет создаётся автоматически после заказа

Регистрация как отдельный шаг исчезает с сайта. Аккаунт и личный кабинет создаются автоматически, когда человек оформил заказ, а данные для входа приходят ему на почту.

## Что меняется для посетителя

1. Никаких кнопок и страниц «Регистрация». В шапке и мобильном меню остаётся только «Войти».
2. Оформление заказа — без входа (уже работает). После успешной отправки заказа система сама заводит кабинет по email из заказа.
3. На почту приходит письмо: номер заказа, логин (его email), временный пароль и кнопка «Войти в кабинет». В письме — просьба сменить пароль после входа.
4. Если человек уже заказывал раньше (аккаунт есть), новый аккаунт не создаётся и пароль не сбрасывается — заказ просто привязывается к существующему кабинету, а в письме указано «войдите под своим паролем» со ссылкой на восстановление.
5. В кабинете при входе с временным паролем показывается баннер «Смените пароль» с переходом к смене (карточка смены пароля уже есть).
6. Кнопки каталога «Заказать»/«Отправить запрос» больше не требуют входа — модалка с предложением войти/зарегистрироваться убирается.

## Что удаляется (проверка «ничего лишнего»)

- Страница `/register` и все ссылки на неё (шапка, мобильное меню, главная, страница входа, модалка авторизации).
- Модалка `AuthPromptDialog`, хелперы `auth-prompt`, `use-require-auth` и их вызовы в карточках каталога.
- Секция настроек «Шапка: Кнопка регистрации» из списка управляемых блоков.
- Страницы `/login`, `/forgot-password`, `/reset-password`, `/profile` остаются — они нужны для входа и кабинета.

## Техническая часть

- `src/lib/orders.functions.ts` (`submitOrder`): после успешного создания заказа и позиций — шаг «обеспечить аккаунт»:
  - поиск пользователя по email через Admin API (`listUsers` с фильтром по email);
  - если нет — `supabaseAdmin.auth.admin.createUser({ email, password: <случайный>, email_confirm: true, user_metadata: { full_name, phone, company, consent_pd } })`; триггер `handle_new_user` создаст профиль;
  - `orders.user_id` проставляется найденному/созданному пользователю (заказ уже создан — делаем `update`);
  - весь блок в try/catch: сбой создания аккаунта не должен ронять заказ, только пишем в `order_timeline` событие `account_created` / ошибку в лог.
- Новый шаблон письма `src/lib/email-templates/account-access.tsx` + регистрация в `registry.ts`: приветствие, номер заказа, email, временный пароль моноширинным блоком, кнопка «Войти в кабинет» (`/login`), примечание про смену пароля. Для существующего аккаунта — вариант без пароля со ссылкой «Восстановить доступ».
- Отправка — через существующий серверный хелпер писем (`src/lib/admin-email.server.ts`, тем же способом, что и `notifyClientOrderConfirmedEmail`), с идемпотентным ключом `account-access-<orderId>`.
- Пароль: 12–14 символов из безопасного алфавита через `crypto.getRandomValues`, генерируется только на сервере, в БД и в ответ клиенту не возвращается, в Telegram-уведомление не попадает.
- Пометка «временный пароль» — в `user_metadata.must_change_password: true`; кабинет читает её и показывает баннер, `ChangePasswordCard` после успешной смены снимает флаг.
- Удаление файлов: `src/routes/register.tsx`, `src/components/AuthPromptDialog.tsx`, `src/lib/auth-prompt.ts`, `src/hooks/use-require-auth.ts`; правки в `SiteChrome.tsx`, `routes/index.tsx`, `routes/login.tsx`, `routes/__root.tsx`, `CatalogDetail.tsx`, `lib/site-sections.tsx`, `order.success.$id.tsx` (вместо «создать аккаунт» — текст «данные для входа отправлены на почту»).
- Регистрация в Supabase Auth отключается (`disable_signup`), чтобы аккаунты появлялись только через заказ; вход по email/паролю и восстановление пароля продолжают работать.

## Проверка после внедрения

- Прогон типов и сборки, поиск «мёртвых» импортов и ссылок на удалённые модули.
- Браузерный сценарий: гостевой заказ из корзины → заказ создан → аккаунт заведён → письмо в очереди → вход по временному паролю → заказ виден в кабинете → смена пароля.
- Повторный заказ с тем же email: новый аккаунт не создаётся, заказ привязан к тому же кабинету.
- Проверка, что нигде на сайте не осталось призывов к регистрации и что каталог, корзина, КП-запрос и админка работают как раньше.
