# Кнопки «Открыть в новом окне» — единый стандарт по всему проекту

Сейчас такая кнопка есть только в двух местах (редакторы КП и промо-КП, живое превью), а в остальных
разделах приходится либо смотреть документ в тесном диалоге, либо вручную копировать ссылку.
Приводим всё к одному виду: одна кнопка, одна логика, одинаковая надпись и иконка.

## Что появится

**1. Просмотр документов (диалог превью)**
- В шапке диалога рядом с «Скачать» появится «Открыть в новом окне» — PDF, HTML, картинки
  открываются во вкладке во весь экран. Сейчас там об этом только написано в подсказке внизу,
  а кнопки нет.

**2. Живое превью в редакторах**
- Документы «Делопроизводство» (договоры, акты, приказы, HR) — кнопка «В новом окне» как в КП.
- Презентации — открыть превью слайдов в отдельном окне (удобно на втором мониторе).
- Финансовые документы — открыть готовый PDF во вкладке.

**3. Переход «Открыть на сайте» из админки**
Везде, где у записи есть публичная страница, добавляется кнопка со стрелкой:
- кейсы, отзывы, посадочные страницы и разделы контента (у блога уже есть — приведём к общему виду);
- карточки каталога в списках (сейчас кнопка есть только внутри редактора);
- DJ Hub: трек и раздел пула/софта на публичном сайте.

**4. Клиентские ссылки**
- Заказ — открыть личный кабинет клиента по ссылке `/my/…`;
- заявка и КП — «Посмотреть как клиент» (в КП уже есть, добавим в заказах и заявках);
- письма и вложения — открыть вложение во вкладке.

**5. Справка и планировщик**
- Статья справки — «Открыть в новой вкладке» (чтобы читать инструкцию рядом с работой);
- события планировщика — открыть событие в Google Календаре.

## Как это будет работать

- Единая кнопка: иконка стрелки, надпись «В новом окне» (для сайта — «Открыть на сайте»),
  размер и стиль как у существующей кнопки в КП.
- Если браузер заблокировал всплывающее окно — понятное уведомление с подсказкой, что разрешить.
- Кнопка неактивна, если ссылки ещё нет (черновик без slug, документ не сохранён) — с подсказкой почему.
- Файлы под авторизацией открываются через уже готовый загрузчик документов, а не «голой» ссылкой,
  чтобы не появлялось окно с ошибкой доступа.

## Технические детали

- Новый `src/lib/open-external.ts`: `openInNewTab(url)` — единая обёртка над `window.open`
  с `noopener,noreferrer`, проверкой блокировки попапов и тостом.
- Новый компонент `src/components/admin/OpenInNewTabButton.tsx` (кнопка + иконка `ExternalLink`,
  props: `href | onResolve`, `label`, `disabled`, `reason`).
- Реестр публичных ссылок `src/lib/public-links.ts`: `publicHrefFor(entity, row)` для
  cases, blog, testimonials, catalog-типов, lp/sections, dj-треков. Логика из
  `CatalogEditor` (`publicHref`) переносится сюда, редактор начинает использовать реестр.
- `DocumentViewerDialog` получает кнопку открытия blob-URL во вкладке (по клику пользователя,
  поэтому блокировки не будет); подсказка внизу переписывается под наличие кнопки.
- `DetachedPreviewButton` переиспользуется в `PaperworkEditor` и редакторе презентаций
  (там, где есть html-превью), без дублирования кода.

## Автопроверки

- Юнит-тесты `open-external`: добавление `noopener,noreferrer`, тост при блокировке попапа.
- Тесты `public-links`: для каждого типа сущности возвращается корректный публичный путь,
  а для черновика без slug — `null` (кнопка отключена).
- Тест соответствия маршрутов: каждый путь из `publicHrefFor` существует в дереве роутов
  (защита от переименования страниц) — по образцу текущего теста целостности ссылок.
- Статическая проверка по исходникам: любой `target="_blank"` содержит `rel` с `noopener`,
  любой `window.open` вызывается через `openInNewTab` (кроме самого хелпера и
  `DetachedPreviewButton`, где нужен именованный дескриптор окна).
- Компонентные тесты `OpenInNewTabButton`: активное/неактивное состояние и вызов открытия.
- Прогон всего набора тестов и проверка типов перед завершением.
