# Event Hub Mail Worker

Мини-сервис на Node, через который админка Event Hub подключается к любым
почтовым ящикам по IMAP/SMTP. Лежит в отдельной папке, потому что серверный
рантайм основного приложения (Cloudflare Workers) не умеет открывать
произвольные TCP-соединения к почтовым серверам.

## Что делает

HTTP-API над `imapflow` + `nodemailer`:

| Метод | Назначение |
|-------|------------|
| `POST /test` | Проверить логин/пароль и доступность IMAP+SMTP |
| `POST /folders` | Получить список папок ящика |
| `POST /messages` | Получить список писем (заголовки или с телами) |
| `POST /message` | Получить одно письмо целиком с вложениями |
| `POST /flag` | Поставить/снять флаги (прочитано, важно) |
| `POST /move` | Переместить письмо в другую папку |
| `POST /delete` | Удалить письмо |
| `POST /send` | Отправить письмо через SMTP + положить копию в Sent |

Все запросы аутентифицируются заголовком `X-Worker-Secret`.

## Деплой на Render (~5 минут)

1. Создайте репозиторий на GitHub и залейте туда содержимое этой папки
   (`mail-worker/`). Можно создать новый репо, например `event-hub-mail-worker`.
2. Зарегистрируйтесь на [render.com](https://render.com) (можно через GitHub).
3. **New +** → **Blueprint** → выберите ваш репозиторий → Render найдёт
   файл `render.yaml` и предложит создать сервис.
4. Подтвердите — Render сам построит Docker-образ и поднимет сервис на
    тарифе Starter во Франкфурте. Секрет `MAIL_WORKER_SECRET`
   сгенерируется автоматически.
5. После деплоя:
   - URL сервиса будет вида `https://event-hub-mail-worker.onrender.com`
     (показан в дашборде Render сверху).
   - Значение `MAIL_WORKER_SECRET` посмотрите в дашборде: ваш сервис →
     **Environment** → значок «глаз» у переменной.
6. Скопируйте оба значения и пришлите команду «готово» — я запрошу их
   через защищённую форму Lovable.

> Важно: с сентября 2025 года Render блокирует исходящие порты SMTP
> 25/465/587 на бесплатных Web Services. Поэтому для отправки через
> hoster.by нужен тариф Starter или другой хостинг с разрешённым SMTP egress.

## Альтернатива: Fly.io

```bash
fly launch --no-deploy           # из папки mail-worker/
fly secrets set MAIL_WORKER_SECRET=$(openssl rand -hex 32)
fly deploy
```

## Локальный запуск (для отладки)

```bash
cd mail-worker
npm install
MAIL_WORKER_SECRET=test123 npm run dev
```

Проверка:
```bash
curl http://localhost:3000/health
```

## Безопасность

- Пароли от почтовых ящиков передаются от приложения к воркеру в теле POST.
  Канал — HTTPS, заголовок-секрет защищает от чужих запросов.
- В приложении пароли хранятся в БД зашифрованными (AES-GCM, ключ
  `MAIL_ENC_KEY`); расшифровка происходит на стороне server function
  перед вызовом воркера.
- Для Gmail/Yandex/Mail.ru используйте **пароли приложений**, а не
  основной пароль аккаунта.
